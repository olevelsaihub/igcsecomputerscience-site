Methods, tables and code: show every step

Carry out a method rather than write prose: convert between binary, denary and hexadecimal, work out file sizes, complete truth and trace tables, write logic statements, follow or complete algorithms, and write or fix pseudocode and Python code.

Command words: Calculate, Convert, Construct, Complete, Amend, Write, DrawUsually 1-6 marksAbout 1 minute per mark; allow longer for code you must type and test.

What Pearson asks

Carry out a method rather than write prose: convert between binary, denary and hexadecimal, work out file sizes, complete truth and trace tables, write logic statements, follow or complete algorithms, and write or fix pseudocode and Python code.

How the marks are earned

Marks are usually split across the steps of the method, so each correct stage can score even if the final answer is wrong. For conversions a mark often goes to each correct part (for example each nibble or hex digit). For file sizes there are marks for each part of the expression and the unit conversion. For code, separate marks go to features such as a sensible variable name, a correct condition, a correct calculation and the right output, so partly working code still earns credit.

Method

  1. Read the exact instruction: number of bits, representation (sign and magnitude, two's complement), units, or language.

    Why: A correct method in the wrong format loses marks.

  2. Write down every step of working, such as place-value headings, each line of a trace or each part of an expression.

    Why: Method marks are given for visible steps, not only the final answer.

  3. For file sizes, build the expression in stages: pixels x bits, then divide by 8 for bytes, add any metadata, then divide by 1000 for each unit step up.

    Why: Each stage is usually worth its own mark.

  4. For tables, fill every row and column in order, changing only what the algorithm changes.

    Why: Skipped or guessed rows break the pattern the marks follow.

  5. For code, use meaningful names, plan the inputs, processes and outputs, then type it and test with a normal, a boundary and an unusual value.

    Why: Marks go to each working feature, and testing catches logic errors.

  6. Check the final answer against the question: right number of bits, units, sign, output wording.

    Why: Small format slips are the most common way to drop the last mark.

Answer frame

Working: step 1 ... step 2 ... step 3 ... -> Final answer: ... (with units or bit count). Code: inputs -> processing -> output, then test.

Common errors

Inferred, not measured: Inferred from the official schemes' credit patterns; not measured student-error statistics.

  • Writing only the final answer, so no method marks are possible if it is wrong.
  • Forgetting to divide by 8 when changing bits into bytes, or mixing 1000 and 1024.
  • Giving the wrong number of bits, or dropping the sign bit in signed binary.
  • Updating a trace table row when the variable did not actually change, or skipping a loop pass.
  • In code, putting the output or a calculation inside the wrong branch of an IF, or using unclear names like x and y.
  • Not testing code, so a simple syntax or logic error remains.

The complete original question is shown; the illustration answers part (d)(ii).

Model answer · written by olevels.com, not an official Pearson mark scheme

Step 1, total pixels: 3579 x 6128. Step 2, total bits for the picture: 3579 x 6128 x 32. Step 3, change bits to bytes: (3579 x 6128 x 32) / 8. Step 4, include the metadata: ((3579 x 6128 x 32) / 8) + 732. Step 5, change bytes to megabytes: (((3579 x 6128 x 32) / 8) + 732) / (1000 x 1000). In Python the same expression is: size_mb = ((3579 * 6128 * 32) / 8 + 732) / (1000 * 1000)

Why it earns the marks

The expression is built one stage at a time, so each part that carries credit is visible: the pixel-times-depth product, the divide by 8, adding the 732 bytes of metadata only after converting to bytes, and the divide by a million for megabytes. The question says no calculation is needed, so no time is spent on the arithmetic.
