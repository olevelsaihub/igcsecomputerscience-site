Knowledge card

Trace tables: run the algorithm by hand

Written

A trace table has a column for each variable and one new row each time a value changes. Dry-run line by line with the real inputs, work out each condition as True or False, and write only what changes.

  • A trace table is a grid with one column for each variable (and often one for outputs) and one new row each time a value changes.
  • Dry-running means following an algorithm line by line with real input values, exactly as the computer would, without guessing.
  • SET x TO 5 in Pearson pseudocode is the same as x = 5 in Python: the old value of x is replaced.
  • A variable keeps its value until a line changes it, so you only write a new value when it actually changes.
  • A WHILE loop tests its condition before each run of the body; a REPEAT ... UNTIL loop runs the body first and tests at the end.
  • MOD gives the remainder after division (7 MOD 2 = 1) and DIV gives the whole-number part (7 DIV 2 = 3); in Python these are % and //.
  • In a flowchart, a diamond is a decision with a Yes and a No exit; follow only the exit that matches the current values.
  • Outputs (SEND ... TO DISPLAY, print or a parallelogram box) are written in the output column at the moment they happen, with the exact text and value.

Before you begin

  • Variables, assignment and the idea that a new value replaces the old one
  • Selection (IF ... THEN ... ELSE) and iteration (WHILE, REPEAT ... UNTIL, FOR)
  • Arithmetic operators including MOD and DIV, and comparison operators such as <, >=, <>
  • Arrays and indexes starting at 0

The method

  1. Start values

    Fill row one before any loop.

  2. Read inputs in order

    One at a time.

  3. Test each condition

    True or False, using current values.

  4. Write changes only

    New row, changed column.

  5. Record outputs

    Exact text and value.

Do not lose marks here

  • ✗
    Boundary slip

    < and <= add or lose a whole row.

  • ✗
    Wrong order

    Update variables in the order written.

  • ✗
    Stop value

    It is still read once inside the loop.

Worked explanation

  1. First row: Colour is empty, and Score, RedPoints, OrangePoints and NumOranges are all 0.
  2. Line 7: Colour is not "-1", so the loop starts. Input red: line 9 is True, so RedPoints becomes 1.
  3. Input orange: line 9 is False, line 12 is True, so OrangePoints becomes 8 and NumOranges becomes 1.
  4. Input red: RedPoints becomes 2. Input red: RedPoints becomes 3.
  5. Input orange: OrangePoints becomes 16 and NumOranges becomes 2.
  6. Input -1: neither test is True, so nothing changes. Back at line 7, Colour is now "-1", so the loop ends.
  7. Line 19: Score = RedPoints + OrangePoints = 3 + 16 = 19.
  8. Lines 21-23 send three outputs. Line 23 sends OrangePoints (16), not the number of oranges, which is why Reba is surprised.
Model answer · written by olevels.com, not an official Pearson mark scheme

Row 1: Colour (blank), Score 0, RedPoints 0, OrangePoints 0, NumOranges 0. Row 2: red, RedPoints 1. Row 3: orange, OrangePoints 8, NumOranges 1. Row 4: red, RedPoints 2. Row 5: red, RedPoints 3. Row 6: orange, OrangePoints 16, NumOranges 2. Row 7: -1, Score 19. Outputs: 'Score: 19', then 'Number of reds: 3', then 'Number of oranges: 16'.

How the marks are earned

One mark for the RedPoints column (1, 2, 3). One mark for OrangePoints and NumOranges together (8 then 16; 1 then 2). One mark for Score 19 appearing on the last row (or the row after). One mark for the three outputs, including the faulty 16 for oranges.

Calculation check

  • sum(1 for c in ['red','orange','red','red','orange'] if c == 'red') = 3
  • sum(8 for c in ['red','orange','red','red','orange'] if c == 'orange') = 16
  • sum(1 for c in ['red','orange','red','red','orange'] if c == 'orange') = 2
  • 3 × 1 + 2 × 8 = 19
