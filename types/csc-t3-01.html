Knowledge card

Binary to denary and back (unsigned, 0 to 255)

Written
  • Binary is base 2: each digit (a bit) is either 0 or 1.
  • Denary is our everyday base 10 number system.
  • In an 8-bit number the place values, from left to right, are 128, 64, 32, 16, 8, 4, 2 and 1.
  • Unsigned means the number has no sign, so it is always zero or positive.
  • With 8 unsigned bits you can store whole numbers from 0 (00000000) to 255 (11111111).
  • A nibble is a group of 4 bits; a byte is 8 bits, or two nibbles.
  • To change binary to denary, add up the place values that sit under each 1.
  • To change denary to binary, take away the biggest place value that fits, write a 1 there, and repeat with what is left.
  • If the bit on the far right (worth 1) is 0, the number is even; if the far-left bit (worth 128) is 1, the number is at least 128.

Before you begin

  • Powers of 2 up to 128
  • Simple subtraction and addition of whole numbers
  • Meaning of bit, nibble and byte

The method

  1. Write the eight place values 128 64 32 16 8 4 2 1 across the top of your working.

    Why: Every bit's worth comes from its column, so a header stops you losing your place.

  2. Denary to binary: start at 128 and ask 'does this fit into what is left?'. If yes write 1 and subtract it; if no write 0.

    Why: Working from the largest value down gives the one correct pattern every time.

  3. Carry on until you reach the 1 column and the amount left is 0.

    Why: A remainder that is not 0 at the end means an arithmetic slip somewhere.

  4. Binary to denary: add the place values above every 1 and ignore the 0s.

    Why: A 0 means that place value is not used.

  5. Write the answer as 8 bits, adding zeros on the left if needed, and leave a space between the two nibbles.

    Why: The question asks for 8 bits, and marks are often given nibble by nibble, so a clear split helps the examiner.

  6. Check by converting your answer back the other way.

    Why: A reverse check catches most mistakes in a few seconds.

Do not lose marks here

  • ✗
    Writing fewer than 8 bits when the question asks for 8-bit binary, for example 111100 instead of 0011 1100.
  • ✗
    Writing the bits in reverse order, so the first nibble and second nibble swap places.
  • ✗
    Starting the place values at 256 or missing one out, which shifts every bit by one place.
  • ✗
    Choosing a negative option in a multiple-choice question about an unsigned number.
  • ✗
    Subtraction slips, which show up as a remainder that is not 0 at the end.

How each command word is answered

Convert4Give the 8-bit pattern (or the denary number) as the final answer, split into two nibbles; short working is fine but the final pattern must be clear.
Give1One value is enough, such as the binary for a sample value read from a graph; leading zeros do not matter unless 8 bits are asked for.

Now see it used on a real past-paper question

What a complete response includes

For a 2-mark conversion, each correct nibble in the right position earns one mark, so the left four bits and the right four bits are judged separately. Short forms (one bit pattern read from a graph, or a multiple-choice choice) earn a single mark.

Worked explanation

  1. Write the headers: 128 64 32 16 8 4 2 1.
  2. 128 does not fit into 60, so write 0. 64 does not fit, so write 0.
  3. 32 fits: write 1; 60 - 32 = 28 left.
  4. 16 fits into 28: write 1; 28 - 16 = 12 left.
  5. 8 fits into 12: write 1; 12 - 8 = 4 left.
  6. 4 fits: write 1; 4 - 4 = 0 left.
  7. Nothing is left, so the 2 and 1 columns are 0.
  8. Pattern: 0011 1100. Check: 32 + 16 + 8 + 4 = 60.
Model answer · written by olevels.com, not an official Pearson mark scheme

0011 1100

How the marks are earned

One mark for the left nibble 0011 and one mark for the right nibble 1100, each in the correct position.

Calculation check

  • format(60, '08b') = 00111100
  • int('00111100', 2) = 60
  • 32 + 16 + 8 + 4 = 60
