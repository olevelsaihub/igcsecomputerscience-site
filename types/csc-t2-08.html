Knowledge card

Syntax, logic and runtime errors

Written
  • A syntax error breaks the grammar rules of the language, so the program will not translate (will not start running).
  • Examples of syntax errors in Python: a missing colon after if, a misspelt keyword, or writing x instead of * to multiply.
  • A logic error lets the program run, but it gives the wrong result or behaves in an unintended way.
  • Examples of logic errors: subtracting the wrong way round, or using > where >= was needed.
  • A runtime error happens while the program is running and makes it crash or stop unexpectedly.
  • Examples of runtime errors: dividing by zero, using an index outside an array, or opening a file that does not exist.
  • To classify an error, ask: does it translate? Does it crash? Does it give the wrong answer?

The method

  1. Read the description of the fault or symptom.

    Why: The symptom tells you the error type.

  2. If the code will not translate or breaks a language rule, it is a syntax error.

    Why: Syntax errors are found before the program can run.

  3. If the program stops or crashes while running, it is a runtime error.

    Why: Runtime errors only appear during execution.

  4. If the program runs to the end but the output is wrong, it is a logic error.

    Why: Logic errors do not stop the program; they give wrong results.

  5. In tick tables, put exactly one tick in each row.

    Why: Each description matches one error type.

Do not lose marks here

  • ✗
    Calling divide by zero a logic error; it crashes the program, so it is a runtime error.
  • ✗
    Calling a wrong-way-round subtraction a syntax error; the code is valid, so it is a logic error.
  • ✗
    Defining runtime error by repeating the question ('an error at runtime') without saying it crashes.
  • ✗
    Giving an example when a definition was asked for.

Common mistakes: Inferred, not measured. Inferred from the official schemes' credit and rejection patterns; not measured student-error statistics.

Worked explanation

  1. Row 1: the program runs but the output is not what was expected. It ran, so it is not syntax; it did not crash, so it is not runtime. Tick Logic.
  2. Row 2: the program does not translate. It broke a language rule. Tick Syntax.
  3. Row 3: the program crashes while it is running. Tick Runtime.
Model answer · written by olevels.com, not an official Pearson mark scheme

Does not produce the expected output: logic error. Does not translate: syntax error. Crashes during execution: runtime error.

How the marks are earned

One mark for each correct tick: logic in row 1, syntax in row 2, runtime in row 3.
