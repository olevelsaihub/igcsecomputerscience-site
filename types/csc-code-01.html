Knowledge card

Fix the errors in a short program

Written
  • A syntax error breaks the rules of the language, so Python refuses to run the program at all (for example a missing colon or bracket).
  • A runtime error happens while the program is running, such as dividing by zero or using a variable name Python has never seen.
  • A logic error lets the program run but gives the wrong answer, such as using % (remainder) where * (multiply) was needed.
  • Python is case-sensitive: count, Count and COUNT are three different names.
  • One = stores a value (assignment); two == compares two values (equality test).
  • Every if, elif, else, while, for and def line must end with a colon.
  • Arguments in a subprogram call are separated by commas, e.g. random.randint(1, 5).
  • The question tells you exactly how many errors there are, and each repaired error earns one mark.

Before you begin

  • Variables and assignment
  • Arithmetic operators + - * / // %
  • Relational operators and if/elif/else
  • How to run a program and read an error message
1

The method

  1. Read the task sentence that says what the program should do, and note how many errors you must find.

    Why: You can only spot a logic error if you know the correct result, and the count tells you when to stop.

  2. Run the program and read the first error message, including its line number.

    Why: Python points straight at syntax and runtime errors, which is the quickest way to find them.

  3. Fix that one error, save, and run again; repeat until the program runs.

    Why: Fixing one thing at a time stops you creating new errors and shows which change worked.

  4. Compare the output with the stated purpose or the test data, and check each operator and comparison.

    Why: Logic errors give no message, so you must test the answer yourself.

  5. Change nothing else, then save with the exact FINISHED file name.

    Why: Marks are only for the stated errors; extra edits risk breaking working lines and the file must be found to be marked.

Do not lose marks here

  • ✗
    Rewriting working lines or adding new features, which wastes time and can introduce new errors.
  • ✗
    Fixing only the errors Python reports and missing the logic error that gives a wrong answer.
  • ✗
    Changing the capitalisation of a name in one place but not in every place it is used.
  • ✗
    Swapping == for = (or the other way round) on the wrong line.
  • ✗
    Forgetting to save the file with the FINISHED name.

Worked explanation

  1. The task: width is random, length is always 4, and the program must show width, length and perimeter. Three errors to find.
  2. Run it. Python stops at line 6: length = ;4 is a syntax error. A value cannot start with a semicolon, so write length = 4.
  3. Run again. Python stops at random.randint (1 5): two arguments need a comma between them, so write random.randint (1, 5).
  4. Run again. It now runs, but the perimeter is wrong. Perimeter of a rectangle = 2 x width + 2 x length, and % means remainder, not multiply. Change 2 % width to 2 * width.
  5. Test: if width is 3 the output should be 3 4 14, because 2 x 3 + 2 x 4 = 14. Run a few times and check each line.
  6. Save as Q02cFINISHED.py.
Model answer · written by olevels.com, not an official Pearson mark scheme

import random

width = 0 length = 4 perimeter = 0

width = random.randint (1, 5) perimeter = (2 * width) + (2 * length)

print (width, length, perimeter)

How the marks are earned

One mark for removing the semicolon so length is set to 4; one mark for the comma between 1 and 5 in the randint call; one mark for using * instead of % in the perimeter line.

Calculation check

  • (2 × 3)+(2 × 4) = 14
  • (2 × 5)+(2 × 4) = 18

Worked program

Written by olevels.com and tested against the paper’s examples.

# Worked example for CSC-CODE-01 (4CP0-2024-JUN-02-standard-Q02-c). Authored by olevels.com; not Pearson's code.
# Q02c

import random

width = 0
length = 4          # Fix 1: the stray semicolon before 4 has been removed
perimeter = 0

width = random.randint (1, 5)                 # Fix 2: a comma now separates the two arguments
perimeter = (2 * width) + (2 * length)        # Fix 3: * (multiply) replaces % (remainder)

print (width, length, perimeter)
