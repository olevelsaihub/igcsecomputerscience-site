Knowledge card

Make an algorithm faster or work for any amount of data

Written
  • An efficient algorithm does the job with fewer steps, such as fewer comparisons, or with less memory.
  • Nested IF ... ELSE stops testing as soon as one condition is True; a list of separate IF statements always tests every condition.
  • Hard-coding means writing a fixed value (such as 8 for the number of items) into the code; it breaks when the data size changes.
  • LENGTH(array) gives the number of items in an array, so a loop such as WHILE i < LENGTH(flavours) works for any size of list.
  • An array stores many values under one name with an index, so one loop can replace many separate variables and IF statements.
  • Generality means the algorithm still works when the amount or values of data change, without rewriting the code.

Before you begin

  • Selection, including nested IF ... ELSE
  • Arrays, indexes and LENGTH
  • WHILE and FOR loops
  • Counting the steps an algorithm takes
1

The method

  1. Find what limits the algorithm: a fixed number, many separate variables, or tests that always run.

    Why: The limiting structure is what the improvement must change.

  2. Count the comparisons each version makes for a typical input.

    Why: Comparing counts gives you a concrete reason for 'more efficient'.

  3. Name the change: nested selection, a loop over an array, or LENGTH instead of a fixed number.

    Why: The first mark is usually for the improvement itself.

  4. Link the change to its benefit: fewer tests are carried out, or it works for any amount of data.

    Why: The second mark needs the consequence, joined to the change.

Do not lose marks here

  • ✗
    Saying one version is 'quicker' or 'shorter' with no reason linked to fewer comparisons.
  • ✗
    Judging efficiency by the number of lines of code instead of the number of operations carried out.
  • ✗
    Suggesting an array without saying that the values can then be processed in a loop.
  • ✗
    Giving the line of the array declaration instead of the loop line that holds the fixed count.

Common mistakes: Inferred, not measured. Inferred from the official schemes' credit and rejection patterns; not measured student-error statistics.

How each command word is answered

Command wordTimes askedWhat to write
Give1Just the line number that needs changing.
State1Say the change in one line, e.g. replace 8 with LENGTH(flavours).
Explain2Improvement or reason plus its linked effect, e.g. nested IFs skip the remaining tests once one is True, so fewer comparisons are made.

Now see it used on a real past-paper question

What a complete response includes

One mark for the improvement or the better choice, and one mark for the linked reason, such as fewer comparisons or working for any length. Single-line answers get the mark for the right line number or the right replacement.

Make an algorithm faster or work for any amount of data · June 2024 · Paper 2 · Question 4 · part (b) · 2 marks

(b) An algorithm reports the range that an integer falls within. Integers from 0 to 39 are in the low range. Integers from 40 to 69 are in the middle range. Integers from 70 to 100 are in the high range. Figure 4 and Figure 5 show two algorithms that solve this problem. SEND ‘Enter an integer: ’ TO DISPLAY RECEIVE theNumber FROM (INTEGER) KEYBOARD IF (theNumber < 40) THEN SEND ‘Low range’ TO DISPLAY ELSE IF (theNumber < 70) THEN SEND ‘Middle range’ TO DISPLAY ELSE SEND ‘High range’ TO DISPLAY END IF END IF Figure 4 SEND ‘Enter an integer: ’ TO DISPLAY RECEIVE theNumber FROM (INTEGER) KEYBOARD IF (theNumber < 40) THEN SEND ‘Low range’ TO DISPLAY END IF IF (theNumber > 39) AND (theNumber < 70) THEN SEND ‘Middle range’ TO DISPLAY END IF IF (theNumber > 69) THEN SEND ‘High range’ TO DISPLAY END IF Figure 5 Explain the reason that the algorithm in Figure 4 is more efficient than the algorithm in Figure 5. (2)

Worked explanation

  1. Both algorithms give the right range, so the question is about how much work they do.
  2. Figure 4 uses IF ... ELSE IF ... ELSE. For 20, the first test (< 40) is True, so no other test is made: 1 test.
  3. For 50 or 85, Figure 4 makes at most 2 tests, because the ELSE handles the last case with no test.
  4. Figure 5 has three separate IF statements, so all three tests are made for every input, even after a match.
  5. So Figure 4 does fewer comparisons, which is more efficient.
Model answer · written by olevels.com, not an official Pearson mark scheme

Figure 4 carries out fewer comparisons, because its tests are nested: once one condition is True the remaining tests are skipped. Figure 5 has three separate IF statements, so all three tests are made every time, even when the first one has already matched.

How the marks are earned

One mark for saying Figure 4 makes fewer tests (or Figure 5 makes more). One linked mark for the reason: nested selection stops once a test is True, while separate IFs are all checked.

Calculation check

  • [1 if n < 40 else 2 for n in [20, 50, 85]] = [1, 2, 2]
  • [3 for n in [20, 50, 85]] = [3, 3, 3]
