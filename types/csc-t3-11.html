Expressions for file size and transfer time

Calculation
  • Image size in bits = width (pixels) x height (pixels) x colour depth (bits per pixel).
  • Sound size in bits = sample rate (samples per second, Hz) x bit depth (bits per sample) x length (seconds).
  • Text size in bytes = number of characters x bytes per character.
  • Divide bits by 8 to get bytes; multiply bytes by 8 to get bits.
  • Metadata (data about the file, such as its size and date) is added on, in bytes, after converting to bytes.
  • Decimal units step by 1000: kB = 1000 bytes, MB = 1000 x 1000 bytes, GB = 1000^3 bytes.
  • Binary units step by 1024: KiB = 1024 bytes, MiB = 1024 x 1024 bytes.
  • Transmission time (s) = file size in bits / transmission speed in bits per second; Mbps means millions of bits per second.
  • 'Construct an expression' means write the calculation, with brackets so the order is clear; you do not have to work it out.

Before you begin

  • Bits, bytes and the factor 8
  • Decimal and binary multiples (CSC-T3-16)
  • Order of operations and brackets
1

The method

  1. Write the basic product: width x height x colour depth (image), rate x bit depth x seconds (sound), or characters x bytes per character (text).

    Why: This gives the raw amount of data.

  2. Convert bits to bytes by dividing by 8 (or bytes to bits by multiplying by 8 for a transfer time).

    Why: Storage units are bytes; network speeds are in bits.

  3. Add any metadata, which is given in bytes, after converting to bytes.

    Why: You can only add amounts in the same unit.

  4. Scale to the unit asked: divide by 1000 x 1000 for MB, or 1024 x 1024 for MiB.

    Why: Each unit has its own factor, and the wrong one loses a mark.

  5. For transmission time, divide the size in bits by the speed in bits per second (for example 54 x 1000 x 1000).

    Why: Time is amount divided by rate.

  6. Use brackets so the order of operations is correct, and round up if you need whole blocks.

    Why: An expression that would calculate wrongly is not fully correct.

Do not lose marks here

  • ✗
    Forgetting to divide by 8 to turn bits into bytes.
  • ✗
    Adding the metadata before dividing by 8, which treats bytes as bits.
  • ✗
    Using 1024 when the question asks for megabytes, or 1000 when it asks for mebibytes.
  • ✗
    Missing brackets, so the expression would divide only part of the total.
  • ✗
    In transfer time, forgetting to change gigabytes into bits or Mbps into bits per second.
  • ✗
    Not rounding up when whole blocks or whole images are needed.

Common mistakes: Inferred, not measured. Inferred from the official schemes' credit and rejection patterns; not measured student-error statistics.

Now see it used on a real past-paper question

What a complete response includes

One mark for each correct part of the expression: the core product, the /8 (or x8) conversion, the metadata, the unit scaling, and dividing by the rate where relevant. A fully correct expression, or the correct calculated value, earns full marks.

Worked explanation

  1. Number of pixels: 3579 x 6128.
  2. Bits for the whole image: 3579 x 6128 x 32.
  3. Change to bytes: (3579 x 6128 x 32) / 8.
  4. Add the metadata, which is already in bytes: (3579 x 6128 x 32) / 8 + 732.
  5. Change bytes to megabytes by dividing by 1000 x 1000.
  6. Put brackets round the top so all of it is divided.
  7. Value if worked out: about 87.73 MB (not required).
Model answer · written by olevels.com, not an official Pearson mark scheme

((3579 x 6128 x 32) / 8 + 732) / (1000 x 1000)

How the marks are earned

One mark for 3579 x 6128 x 32, one for dividing by 8, one for adding 732, and one for dividing by 1000 x 1000.

Calculation check

  • ((3579 × 6128 × 32) ÷ 8 + 732) ÷ (1000 × 1000) = 87.73
  • 3579 × 6128 × 32 ÷ 8 = 87728448
  • (3579 × 6128 × 4 + 732) ÷ 10 × × 6 = 87.73
