Knowledge card

Compare sorts and searches

Written
  • A linear search checks items one by one from the first until it finds the target or reaches the end of the list.
  • A linear search works on sorted or unsorted lists and is simple to write.
  • A binary search needs a sorted list but halves the search area with each comparison, so it needs far fewer comparisons on a large list.
  • For 1000 sorted items, a binary search needs at most 10 comparisons; a linear search may need all 1000.
  • Bubble sort sorts in place, so it uses very little extra memory (one temporary variable for swaps), but it is slow on large lists.
  • Merge sort is usually much faster on large lists, but it needs extra memory to hold the split and merged lists.
  • Choosing an algorithm depends on the data: its size, whether it is sorted, and how much memory is available.

Before you begin

  • How bubble sort, merge sort, linear search and binary search work
  • Ideas of time (number of steps) and memory

The method

  1. Name the algorithm involved and recall its key property (needs sorted data, halves the list, sorts in place, creates extra lists).

    Why: Every answer grows from that one property.

  2. Link the property to a consequence: speed on large lists, memory used, or simplicity.

    Why: Explain marks need the property and its effect joined together.

  3. Use the scenario's details (size of list, sorted or not) in a choice question.

    Why: A justification must fit the data described.

  4. Do not repeat facts given in the question as your justification.

    Why: Restating 'the list is sorted' when the question says so earns nothing.

Do not lose marks here

  • ✗
    Saying binary search is 'faster' with no reason, such as halving or fewer comparisons.
  • ✗
    Giving 'the list is sorted' as a justification when the question already states it.
  • ✗
    Mixing up which sort works in place and which needs extra memory.
  • ✗
    Describing a linear search without saying when it stops.
  • ✗
    Listing two advantages that are really the same point.

Common mistakes: Inferred, not measured. Inferred from the official schemes' credit and rejection patterns; not measured student-error statistics.

How each command word is answered

Command wordTimes askedWhat to write
State3One short point per mark, e.g. 'works on unsorted lists'. For state-and-justify, name the algorithm first, then give the reason.
Give1Just the name, e.g. bubble sort.
Explain3Point plus linked reason, e.g. more memory is needed because the list is split into many new lists.
Describe1The steps in order: where it starts, what is compared, and when it stops.

What a complete response includes

State items earn one mark per valid point. Explain items earn a mark for the point and a mark for its linked consequence. Select-and-justify items earn one mark for the right algorithm and one for a reason that fits the data.

Worked explanation

  1. The data: over 1000 items, already sorted in ascending order.
  2. Sorted data allows a binary search, and a large list is where binary search gains most.
  3. Justify with how it works: each comparison halves the part of the list still to search.
  4. Back it with numbers: 1000 can be halved about 10 times, so about 10 comparisons at most, compared with up to 1000 for a linear search.
Model answer · written by olevels.com, not an official Pearson mark scheme

Search algorithm: binary search. Justification: each comparison with the middle item throws away half of the remaining list, so even with 1000 items it needs only about 10 comparisons, far fewer than checking items one at a time.

How the marks are earned

One mark for naming binary search. One mark for the justification: the list is halved each time, so fewer comparisons are needed.

Calculation check

  • len(bin(1000)) - 2 = 10
  • pow(2, 10) >= 1000 and pow(2, 9) < 1000 = True
