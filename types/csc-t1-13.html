Knowledge card

Decomposition and abstraction

Written
  • Computational thinking is a set of problem-solving skills used before and while writing programs; decomposition and abstraction are two of them.
  • Decomposition means splitting a big problem into smaller sub-problems that can each be solved, coded and tested separately.
  • Planning comments such as '// roll dice 3 times' and '// calculate final score' are decomposition: each comment is one smaller task.
  • Abstraction means hiding or leaving out the details that do not matter, so you can focus on what does.
  • Using a library subprogram (such as a random number function) is abstraction: you use what it returns without needing to know how it works inside.
  • A model of the real world (such as a dice game) is an abstraction because it keeps only the features the program needs.

The method

  1. Decide which idea is asked: splitting into parts (decomposition) or hiding detail (abstraction).

    Why: Mixing them up loses every mark.

  2. Give the meaning of the term in your own words.

    Why: The first mark is usually for the meaning.

  3. Point to the exact place in the scenario that shows it.

    Why: The second mark needs the link to this scenario.

  4. Join the two with 'because' or 'so'.

    Why: A linked explanation is what earns both marks.

Do not lose marks here

  • ✗
    Swapping the definitions of decomposition and abstraction.
  • ✗
    Giving a definition with no link to the scenario in a 2-mark explain.
  • ✗
    Saying abstraction is 'modelling the real world' when the question already says so.
  • ✗
    Describing what the library does (makes random numbers) instead of why using it hides detail.

Worked explanation

  1. The idea asked for is abstraction: hiding detail that does not matter.
  2. In the scenario, Eli calls a ready-made library subprogram to get a random dice number.
  3. He does not need to know how the subprogram produces the number; he only uses the result.
  4. Join them: meaning, then link.
Model answer · written by olevels.com, not an official Pearson mark scheme

Abstraction means hiding detail that is not needed. Eli only needs the dice number that the library subprogram gives back, so he can ignore how it generates that number and concentrate on writing his own game code.

How the marks are earned

One mark for the meaning (ignoring or hiding detail that is not needed). One linked mark for applying it: how the library makes the random number does not matter to Eli, because he only needs the result.
