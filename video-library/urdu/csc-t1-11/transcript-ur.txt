Idea۔ تصور کریں کہ آپ dictionary میں ایک word ڈھونڈ رہے ہیں۔ آپ شروع سے ہر page پڑھ سکتے ہیں۔ یا آپ اسے درمیان کے قریب کھول کر آگے یا پیچھے جا سکتے ہیں۔ دونوں طریقوں سے word مل جاتا ہے، مگر ایک بہت تیز ہے۔ صحیح algorithm چننا اہم ہے۔ دو searches جاننی ہیں۔ Linear search شروع سے items ایک ایک کر کے check کرتی ہے، جب تک target مل نہ جائے یا آخر نہ آ جائے۔ یہ کسی بھی list پر کام کرتی ہے۔ Binary search درمیانی item check کرتی ہے اور ہر بار list کو آدھا کرتی ہے، مگر list کا sorted ہونا ضروری ہے۔ دو sorts جاننی ہیں۔ Bubble sort ساتھ والوں کو swap کرتی ہے اور in place sort کرتی ہے، اس لیے اسے بہت کم extra memory چاہیے، مگر بڑی lists پر یہ سست ہے۔ Merge sort بڑی lists پر بہت تیز ہے، مگر اسے ان تمام نئی lists کے لیے extra memory چاہیے جو یہ بناتی ہے۔ یاد رکھنے کا ایک number یہ ہے۔ ایک ہزار sorted items کے لیے، linear search کو پورے ایک ہزار checks لگ سکتے ہیں۔ Binary search کو زیادہ سے زیادہ دس لگتے ہیں۔

Method۔ جواب دینے کے لیے، algorithm کا نام لیں اور اس کی key property یاد کریں: کیا اسے sorted data چاہیے، کیا یہ list کو آدھا کرتی ہے، کیا یہ in place sort کرتی ہے؟ پھر اس property کو لفظ so کے ساتھ ایک اثر سے جوڑیں۔ صرف faster کہنے پر کچھ نہیں ملتا۔ وجہ بتائیں: یہ ہر بار list کو آدھا کرتی ہے، so کم comparisons چاہییں۔ اور جو بات question پہلے ہی دے چکا ہو، اسے کبھی نہ دہرائیں۔

Worked Example۔ یہ جون دو ہزار پچیس کے Paper دو کا اصل question ہے۔ ایک youth club کھیلوں کے سامان کی ہزار سے زیادہ items کی list رکھتا ہے، ascending order میں sorted۔ سب سے مناسب search algorithm State کریں اور justify کریں۔ یہ دو marks کا ہے۔ Data پڑھیں۔ List بڑی ہے، اور پہلے سے sorted ہے۔ Sorted list binary search کو ممکن بناتی ہے، اور بڑی list وہ جگہ ہے جہاں اسے سب سے زیادہ فائدہ ہوتا ہے۔ اسے یہ بتا کر justify کریں کہ یہ کیسے کام کرتی ہے۔ درمیانی item سے ہر comparison آدھی list پھینک دیتی ہے۔ ایک ہزار items پانچ سو رہ جاتی ہیں، پھر دو سو پچاس، اور اسی طرح ایک تک۔ یہ زیادہ سے زیادہ دس comparisons ہیں، جبکہ linear search میں ایک ہزار تک ہو سکتی ہیں۔ تو answer ہے binary search، کیونکہ ہر comparison بچی ہوئی list کو آدھا کرتی ہے، so بہت کم comparisons چاہییں۔ نام پر ایک mark، وجہ پر ایک۔ یہ وضاحت olevels dot com کی ہے، یہ official mark scheme نہیں ہے۔

Common Mistake۔ ایک عام غلطی وجہ کے طور پر یہ دینا ہے کہ list sorted ہے۔ Question پہلے ہی یہ بتا چکا ہے، اس لیے اس پر کچھ نہیں ملتا۔ اس کی جگہ halving والی وجہ دیں۔ ایک اور غلطی memory میں گڑبڑ کرنا ہے۔ Merge sort کو extra memory چاہیے، کیونکہ یہ نئی lists بناتی ہے۔ Bubble sort in place sort کرتی ہے۔

Your Turn۔ اب آپ کوشش کریں۔ ایک چھوٹے sensor کے پاس بہت کم memory ہے۔ اسے پچاس readings sort کرنی ہیں۔ کیا اسے bubble sort استعمال کرنی چاہیے یا merge sort؟ اپنا انتخاب justify کریں۔ رک کر فیصلہ کریں۔

Answer۔ Key fact ہے بہت کم memory۔ Merge sort نئی lists بناتی ہے، اس لیے اسے extra memory چاہیے۔ Bubble sort in place sort کرتی ہے، swaps کے لیے صرف ایک extra variable استعمال کرتے ہوئے۔ تو bubble sort چنیں، کیونکہ یہ in place sort کرتی ہے، so بہت کم extra memory چاہیے۔ پچاس readings چھوٹی list ہے، اس لیے اس کی سست رفتار سے ذرا فرق نہیں پڑتا۔ Method یاد رکھیں۔ algorithm کا نام لیں، اس کی key property دیں، اسے so کے ساتھ اثر سے جوڑیں، اور data پر فٹ کریں۔ اب اس type کے practice questions کریں۔
