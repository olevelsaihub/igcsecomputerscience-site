Idea۔ اپنی صبح کا سوچیں۔ آپ اٹھتے ہیں، منہ دھوتے ہیں، پھر کپڑے پہنتے ہیں، ترتیب سے۔ یہ sequence ہے۔ اگر بارش ہو رہی ہو، تو آپ چھتری لیتے ہیں۔ یہ selection ہے۔ آپ دانت اس وقت تک صاف کرتے رہتے ہیں جب تک وہ صاف نہ ہو جائیں۔ یہ iteration ہے۔ Selection کا مطلب ہے کہ program condition کے ذریعے راستہ چنتا ہے۔ Pseudocode میں یہ IF سے شروع ہوتا ہے۔ اگر rain TRUE ہو تو ایک message دکھایا جاتا ہے۔ ورنہ ELSE والا message دکھایا جاتا ہے۔ Flowchart میں arrows دیکھیں۔ Decision diamond جس کے دونوں راستے آگے نیچے جاری رہیں، selection ہے۔ اگر کوئی arrow اوپر کسی پچھلے step پر واپس جائے، تو steps repeat ہوتے ہیں۔ یہ iteration ہے، جسے loop بھی کہتے ہیں۔ Loop کی تین قسمیں ہیں۔ Count-controlled loop، FOR، fixed تعداد میں repeat ہوتا ہے۔ Pre-conditioned loop، WHILE، پہلے test کرتا ہے، اس لیے ہو سکتا ہے یہ صفر بار چلے۔ Post-conditioned loop، REPEAT UNTIL، آخر میں test کرتا ہے، اس لیے یہ کم از کم ایک بار ضرور چلتا ہے۔

Method۔ پہلے keyword یا shape دیکھیں۔ IF، یا ایسا diamond جس میں loop back نہ ہو، selection ہے۔ FOR، WHILE، REPEAT، یا اوپر واپس جانے والا arrow، iteration ہے۔ Loop کی قسم کے لیے، دیکھیں کہ condition کہاں ہے۔ FOR count-controlled ہے۔ اوپر WHILE pre-conditioned ہے۔ نیچے UNTIL post-conditioned ہے۔ Why this loop والے question کے لیے، ڈھونڈیں کہ loop کو کیا روکتا ہے۔ پھر فائدہ دیں، اور اسے because کے ساتھ اس stopping condition سے جوڑیں۔

Worked Example۔ یہ جون دو ہزار پچیس کے Paper ایک کا اصل question ہے۔ Lines دس سے پندرہ post-conditioned loop استعمال کرتی ہیں۔ ایک وجہ Explain کریں کہ یہ count-controlled loop سے بہتر کیوں ہے۔ یہ دو marks کا ہے۔ ہر pass testNum میں ایک add کرتا ہے، پھر چیک کرتا ہے کہ testNum، number کو پوری طرح divide کرتا ہے یا نہیں۔ اگر remainder صفر ہو تو flag TRUE بن جاتا ہے۔ Loop تب رکتا ہے جب testNum، number تک پہنچ جائے، یا جب flag TRUE ہو۔ Number equals نو آزمائیں۔ Pass ایک: testNum دو ہے، اور نو mod دو ایک ہے، اس لیے flag FALSE رہتا ہے۔ Pass دو: testNum تین ہے، اور نو mod تین صفر ہے، اس لیے flag TRUE بن جاتا ہے۔ Loop صرف دو passes کے بعد رک جاتا ہے۔ دو سے نو تک count-controlled loop ہمیشہ آٹھ passes کرتا، حتیٰ کہ answer معلوم ہونے کے بعد بھی۔ یہ چھ فضول passes ہیں۔ تو answer ہے: یہ زیادہ efficient ہے، کیونکہ جیسے ہی number کا factor مل جائے loop ختم ہو جاتا ہے، جبکہ count-controlled loop چلتا رہتا۔ یہ وضاحت olevels dot com کی ہے، یہ official mark scheme نہیں ہے۔

Common Mistake۔ ایک عام غلطی WHILE loop کو count-controlled کہنا ہے کیونکہ یہ counter استعمال کرتا ہے۔ یہ condition test کرتا ہے، اس لیے یہ condition-controlled ہے۔ ایک اور غلطی ایسا فائدہ دینا ہے جس کا algorithm سے تعلق نہ ہو۔ بتائیں کہ اس loop کو جلد کیا روکتا ہے۔

Your Turn۔ اب آپ کوشش کریں۔ استعمال ہونے والے loop کی قسم کا نام بتائیں۔ پھر ایک وجہ Explain کریں کہ یہاں یہ count-controlled loop سے بہتر کیوں ہے۔ رک کر حل کریں۔

Answer۔ Keyword WHILE ہے، اور condition اوپر test ہوتی ہے، ہر pass سے پہلے۔ تو یہ pre-conditioned loop ہے۔ Ava دوسرا نام ہے، اس لیے pass دو پر found TRUE بن جاتا ہے اور loop رک جاتا ہے۔ Count-controlled loop چھ کے چھ نام چیک کرتا۔ So یہ زیادہ efficient ہے، کیونکہ نام ملتے ہی رک جاتا ہے۔ Method یاد رکھیں۔ keyword یا shape پہچانیں، دیکھیں test کہاں ہے، پھر because کے ساتھ فائدہ دیں۔ اب اس type کے practice questions کریں۔
