Idea۔ Birthday party کی planning بڑا کام لگتی ہے۔ تو آپ اسے بانٹ دیتے ہیں: invitations، food، music اور games۔ ہر چھوٹا کام اکیلے plan کرنا آسان ہے۔ بڑے مسئلے کو چھوٹے مسائل میں بانٹنا decomposition کہلاتا ہے۔ اب metro map کا سوچیں۔ وہ stations، lines اور stops کی ترتیب دکھاتا ہے۔ وہ سڑکیں، عمارتیں اور اصل فاصلے چھوڑ دیتا ہے، کیونکہ آپ کو ان کی ضرورت نہیں۔ جو تفصیل اہم نہیں اسے چھپانا abstraction کہلاتا ہے۔ Program میں decomposition اکثر planning comments کی شکل میں نظر آتی ہے۔ ہر comment ایک چھوٹے task کا نام لیتا ہے، جسے پھر الگ سے لکھا اور test کیا جا سکتا ہے۔ Abstraction تب نظر آتی ہے جب آپ library subprogram استعمال کرتے ہیں۔ یہاں random dot randint ایک سے چھ تک کا number دیتا ہے۔ آپ result استعمال کرتے ہیں، یہ جانے بغیر کہ یہ اندر سے کیسے کام کرتا ہے۔

Method۔ پہلے طے کریں کہ کون سا idea پوچھا گیا ہے: حصوں میں بانٹنا، یا تفصیل چھپانا۔ اس کا مطلب اپنے الفاظ میں دیں۔ پھر scenario میں صحیح جگہ کی نشاندہی کریں، اور دونوں کو because یا so سے جوڑیں۔

Worked Example۔ یہ جون دو ہزار پچیس کے Paper دو کا اصل question ہے۔ Eli ایک dice game design کر رہا ہے۔ وہ dice throw کی model بنانے والے random numbers کے لیے library subprogram استعمال کرتا ہے۔ Explain کریں کہ یہ abstraction کی مثال کیوں ہے۔ یہ دو marks کا ہے۔ پوچھا گیا idea abstraction ہے، جس کا مطلب ہے وہ تفصیل چھپانا جس کی ضرورت نہیں۔ Eli ایک ready-made subprogram call کرتا ہے اور اسے dice کا number واپس ملتا ہے۔ تفصیل کو دو گروپوں میں بانٹیں۔ random number کیسے بنتا ہے، یہ چھپا ہوا ہے، کیونکہ Eli کو اس کی ضرورت نہیں۔ Number خود، اور اس کے اپنے game rules، وہ ہیں جن کے ساتھ وہ کام کرتا ہے۔ تو answer ہے: abstraction کا مطلب ہے وہ تفصیل چھپانا جس کی ضرورت نہیں۔ Eli کو صرف وہ dice number چاہیے جو subprogram return کرتا ہے، so وہ یہ نظر انداز کر سکتا ہے کہ وہ کیسے بنتا ہے اور اپنے game پر توجہ دے سکتا ہے۔ یہ وضاحت olevels dot com کی ہے، یہ official mark scheme نہیں ہے۔

Common Mistake۔ سب سے عام غلطی دونوں definitions کو الٹ دینا ہے۔ مسئلے کو چھوٹے حصوں میں توڑنا decomposition ہے، abstraction نہیں۔ ایک اور غلطی یہ بیان کرنا ہے کہ library کیا کرتی ہے، اس کی جگہ یہ بتانے کے کہ اسے استعمال کرنے سے تفصیل کیوں چھپتی ہے۔

Answer۔ ہر comment ایک چھوٹا task ہے: menu دکھانا، order لینا، اور price نکالنا۔ تو answer ہے: decomposition کا مطلب ہے مسئلے کو چھوٹے sub-problems میں بانٹنا۔ Mina نے اپنی app کو تین چھوٹے tasks میں بانٹا ہے، so ہر ایک کو الگ code اور test کیا جا سکتا ہے۔ Method یاد رکھیں۔ بانٹنا decomposition ہے، چھپانا abstraction ہے۔ مطلب دیں، پھر because کے ساتھ اسے scenario سے جوڑیں۔ اب اس type کے practice questions کریں۔
