Idea۔ چائے کا ایک کپ بنانے کا سوچیں۔ آپ پانی ابالتے ہیں، کپ میں tea bag ڈالتے ہیں، پانی انڈیلتے ہیں، پھر انتظار کرتے ہیں۔ ہر step واضح ہے، اور ترتیب اہم ہے۔ کسی مسئلے کو حل کرنے والے steps کی درست، ترتیب وار list کو algorithm کہتے ہیں۔ ایک ہی algorithm چار طریقوں سے لکھا جا سکتا ہے: flowchart کے طور پر، pseudocode کے طور پر، سادہ English میں written description کے طور پر، یا program code کے طور پر۔ Flowchart steps کو shapes کی شکل میں بناتا ہے جو arrows سے جڑی ہوتی ہیں۔ Rounded box، start یا stop ہے۔ Parallelogram، input یا output ہے۔ Rectangle، process ہے، اور diamond، decision۔ اسے سمجھنے کے لیے programming کا علم نہیں چاہیے۔ Pseudocode code جیسا لگتا ہے، مگر اس میں SET، WHILE اور SEND جیسے سادہ English الفاظ ہوتے ہیں۔ یہ کسی ایک language کے exact rules، یعنی syntax، کا پابند نہیں۔ یہاں loop تین کپ چائے بناتا ہے۔ Algorithm کو test کرنے کے لیے ہم trace table استعمال کرتے ہیں۔ اس میں ہر variable اور output کا ایک column ہوتا ہے۔ ہر row algorithm چلنے کے دوران values دکھاتی ہے۔ ہم اسے ہاتھ سے بھرتے ہیں تاکہ logic follow کریں اور logic errors ڈھونڈیں۔

Method۔ پہلے بالکل طے کریں کہ پوچھا کیا جا رہا ہے۔ کیا یہ definition ہے، feature، benefit، یا کسی audience کے لیے method کا انتخاب؟ ہر ایک کو مختلف مختصر answer چاہیے۔ انتخاب کے لیے، پہلے method کا نام لیں۔ پھر ایسی وجہ دیں جو audience کے مطابق ہو۔ وجہ پر mark تب ہی ملتا ہے جب کوئی مناسب method بتایا گیا ہو۔ Multiple choice میں وہ options خارج کریں جو algorithm لکھنے کے طریقے نہیں ہیں۔ Truth table logic کو test کرتی ہے۔ Cipher encryption کے لیے ہے۔ Simulation حقیقی دنیا کی model بناتی ہے۔

Worked Example۔ یہ جون دو ہزار تئیس کے Paper ایک کا اصل question ہے۔ ایک programmer کچھ non-technical managers کو نیا algorithm دکھا رہا ہے۔ اسے لکھنے کا ایک مناسب method State کریں، اور اپنے answer کو justify کریں۔ یہ دو marks کا ہے۔ Audience سے شروع کریں۔ Managers non-technical ہیں، اس لیے انہیں کوئی programming language نہیں آتی۔ ہمیں ایسا method چاہیے جسے وہ code کے بغیر follow کر سکیں۔ Flowchart بہترین انتخاب ہے۔ ہر step ایک shape ہے، جو arrows سے جڑی ہے، اس لیے کوئی بھی ترتیب اور decisions کو follow کر سکتا ہے۔ تو answer ہے: method، flowchart۔ Justification: یہ steps کو shapes اور arrows کے ساتھ بصری طور پر دکھاتا ہے، so managers اسے code syntax جانے بغیر follow کر سکتے ہیں۔ یہ وضاحت olevels dot com کی ہے، یہ official mark scheme نہیں ہے۔

Common Mistake۔ ایک عام غلطی یہ کہنا ہے کہ algorithm ایک program ہے۔ Program، algorithm لکھنے کا صرف ایک طریقہ ہے۔ ایک اور غلطی ایسی وجہ دینا ہے جو audience کے مطابق نہ ہو۔ یہ کہنا کہ pseudocode اصل code کے قریب ہے، ان managers کے کام نہیں آتا جو code نہیں پڑھ سکتے۔

Your Turn۔ اب آپ کوشش کریں۔ Programmers کی ایک team algorithm کو Python اور Java دونوں میں بدلے گی۔ Algorithm لکھنے کا ایک مناسب method State کریں، اور اپنے answer کو justify کریں۔ رک کر حل کریں۔

Answer۔ Audience programmers ہیں، اس لیے وہ code پڑھ سکتے ہیں۔ Pseudocode ان کے لیے موزوں ہے۔ اس میں code جیسی structure ہوتی ہے، مگر یہ کسی ایک language کے syntax کا پابند نہیں، so اسے Python یا Java میں بدلا جا سکتا ہے۔ Method یاد رکھیں۔ طے کریں کہ audience کون ہے، method کا نام لیں، پھر ان کے مطابق وجہ دیں۔ اب اس type کے practice questions کریں۔
