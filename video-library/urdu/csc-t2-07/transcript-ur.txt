Idea۔ تصور کریں کہ آپ اپنا pencil ایک گندے کمرے میں ڈھونڈ رہے ہیں، پھر ایک صاف کمرے میں۔ Code بھی ایسا ہی ہے۔ یہ program کام کرتا ہے، مگر a اور b کیا ہیں؟ یہ کس لیے ہے؟ کسی اور programmer کو اسے ٹھیک کرنے میں مشکل ہوگی۔ یہ وہی program ہے جسے readable بنایا گیا ہے۔ ایک comment بتاتا ہے کہ یہ کیا کرتا ہے۔ Names بتاتے ہیں کہ ہر value میں کیا ہے۔ Blank lines sections کو الگ کرتی ہیں، اور print line کو if کے اندر indent کیا گیا ہے۔ تو چار techniques ہیں۔ Comments، جو hash sign سے شروع ہوتے ہیں اور computer انہیں نظر انداز کرتا ہے۔ Descriptive names، جیسے t p کی جگہ total pay۔ Structure دکھانے کے لیے indentation۔ اور sections کے درمیان white space۔ Indentation صرف صفائی نہیں ہے۔ Lines کو اندر کی طرف کرنے سے پتا چلتا ہے کہ کون سی lines loop یا if کے اندر آتی ہیں۔ یہاں Revise indented ہے، اس لیے یہ تین بار repeat ہوتا ہے۔ Exam indented نہیں ہے، اس لیے یہ loop کے بعد ایک بار print ہوتا ہے۔

Method۔ پہلے چیک کریں کہ question technique چاہتا ہے یا reason۔ Technique وہ ہے جو programmer کرتا ہے۔ Reason وہ ہے جو یہ پڑھنے والے کے لیے حاصل کرتا ہے۔ Technique کے لیے، list میں سے ایک کا نام لیں اور اگر جگہ ہو تو ایک چھوٹی مثال شامل کریں۔ Comments کی reason کے لیے، بتائیں کہ وہ کسی شخص کو code سمجھنے میں کیسے مدد دیتے ہیں۔

Worked Example۔ یہ نومبر دو ہزار اکیس کے Paper دو کا اصل question ہے۔ ایک technique Give کریں جو programmers اپنے code کو پڑھنے اور سمجھنے میں آسان بنانے کے لیے استعمال کرتے ہیں۔ یہ ایک mark کا ہے۔ Command word give ہے، اور یہ technique مانگتا ہے۔ تو programmer کا کوئی عمل بتائیں۔ List میں سے ایک چنیں: comments، descriptive names، indentation یا white space۔ اسے چند الفاظ اور ایک چھوٹی مثال کے ساتھ لکھیں۔ Give variables descriptive names, for example total pay instead of t p۔ اس پر mark ملتا ہے۔ یہ وضاحت olevels dot com کی ہے، یہ official mark scheme نہیں ہے۔

Common Mistake۔ ایک عام غلطی ایسی چیز دینا ہے جو readability پر اثر نہیں ڈالتی، جیسے use correct code یا use suitable data structures۔ ایک اور غلطی یہ کہنا ہے کہ comments program کو تیز چلاتے ہیں۔ Computer comments کو مکمل نظر انداز کرتا ہے۔ وہ صرف لوگوں کے لیے ہیں۔

Your Turn۔ اب آپ کوشش کریں۔ ایک reason بتائیں کہ programmers اپنے code میں comments کیوں شامل کرتے ہیں۔ پھر comments کے علاوہ ایک اور technique بتائیں جو code کو پڑھنا آسان بناتی ہو۔ رک کر حل کریں۔

Answer۔ A، comments explain کرتے ہیں کہ code کا ایک section کیا کرتا ہے اور کیسے کام کرتا ہے، تاکہ کوئی اور programmer سمجھ سکے۔ B، indentation استعمال کریں تاکہ دکھایا جا سکے کہ کون سی lines loop یا if کے اندر آتی ہیں۔ Descriptive names یا white space بھی صحیح ہوں گے۔ Method یاد رکھیں۔ طے کریں کہ یہ technique ہے یا reason، پھر ایک واضح idea ایک چھوٹی مثال کے ساتھ دیں۔ اب اس type کے practice questions کریں۔
