A flowchart is like a map of an algorithm, the step-by-step plan. Each shape turns into a piece of Python. A rectangle becomes an assignment. A parallelogram becomes input or output. A diamond becomes if, and an arrow that loops back becomes while. Pseudocode maps across too. Set becomes equals. Receive becomes int of input. D I V becomes two slashes, for whole-number division, and M O D becomes the per cent sign, for the remainder. A loop needs a variable that changes inside it, or it never stops. Here count goes up by one each time, so after three passes count less than three is False, and the loop ends.

Tick each box of the design as you code it. Write the starting values first, then the inputs with int. Next, turn every loop-back arrow into a while line with exactly the same condition. Code each decision as if and else, each calculation with the right operator, and add clear outputs. Then run it with the test data and compare.

Here is a real question from Paper 2 in June 2023. The flowchart raises a base to the power of an exponent. We turn it into Python. It is worth ten marks. First, initialise the variables. Base starts at one, anything but zero, so the main loop can start. Exponent zero, answer one, count zero. The arrows lead back to enter value for base, until base is zero. So write while base is not equal to zero, and input the base at the top of the loop. Only carry on if base is not zero. Input the exponent. If it is negative, print an error message. Otherwise, set answer to one and count to zero. While count is less than exponent, answer equals answer times base, and count goes up by one. That multiplies the base exponent times. When the inner loop ends, print the result with a clear label. Run it. Three to the power four gives eighty-one. Five with minus one gives the error. Zero stops the program. This explanation is by olevels.com, not an official mark scheme.

A common mistake is using if where the design loops back. An if runs only once, so the program stops after one go. Another mistake is forgetting to update the loop variable. Without count equals count plus one, the inner loop never ends.
