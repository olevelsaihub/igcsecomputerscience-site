Idea. Before a bank opens a new vault, it might pay an expert to try to break in. If the expert finds a weak door, it is fixed before a real thief tries. A weakness that an attacker could use is called a vulnerability. There are four ways to find weaknesses. Penetration testing is an authorised, pretend attack on your own system. Ethical hackers break in with permission. Analysis tools scan automatically. And policies are reviewed regularly. Software is protected too. In a code review, other programmers check the code. An audit trail records who did what. Modular testing tests each subprogram as it is written. Secure design builds security in from the start. Ethical hackers, or white hat hackers, have the owner's permission. They do not steal or change any data. They report what they find, so it can be fixed. An audit trail is an automatic record of what was done and who did it. Here, a guest deleting a file late at night stands out as suspicious, and can be traced back.

Method. Identify the method named. Say what it does in one plain sentence. Then link it to security: how it finds or prevents weaknesses before attackers use them. Avoid copying words from the question.

Worked example. Here is a real question from Paper 1 in June 2025. I T teams carry out network penetration testing. Describe the purpose of penetration testing. It is worth two marks. Start with what it is: an authorised, simulated attack on the organisation's own network. Its purpose is to find weaknesses before real attackers do. Then say what happens next. The weaknesses are reported and fixed, so the network becomes harder to break into. This explanation is by olevels.com, not an official mark scheme.

Common mistake. A common mistake is saying a penetration tester steals data. They only find and report weaknesses, with permission. Another mistake is calling an audit trail a backup. It is not a copy of the files. It is a record of who did what, and when.

Your turn. Now you try. A games company is about to release an app. Describe how a code review and modular testing could help make it secure. Pause here and work it out.

Answer. In a code review, other programmers check the code to find bugs and security holes before release. In modular testing, each subprogram is tested on its own as it is written, so errors are found early, in a small piece of code.
