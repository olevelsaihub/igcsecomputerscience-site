Find and fix errors in an algorithm

Idea. Imagine a recipe that says bake for three hundred minutes instead of thirty. You can follow every step, but the cake burns. In an algorithm, this is a logic error: it runs, but the result is wrong. Most exam errors are one of four kinds. A boundary that uses the wrong comparison. A loop that goes past the end of an array. A counter that is replaced instead of increased. Or a stopping value counted as data. Array indexes start at zero. This array has seven items, so its indexes go from zero to six. LENGTH is seven, so index seven does not exist.

Method. First, read what the algorithm should do, and note the expected result. Then dry-run it with the test data. The first row where a value goes wrong points to the faulty line. Then write the corrected line in full, in the same pseudocode style, changing only the faulty part. Finally, run the test data again with your fix.

Worked example. Here is a real question from Paper 1 in June 2024. The algorithm should count how many trains were early, on time, or late. There are four errors. This part asks for the correct code for line eleven, for one mark. Here is Figure 2. It stores seven arrival times, then loops through them. Line ten and below count the late and early trains, and lines twenty-two to twenty-four display the totals. Look at line eleven. It sets late to arrival of index. That copies the number of minutes into late, replacing what was there. Dry-run it, row by row. The early train changes nothing. The train one minute late makes late one. The train five minutes late makes late five, not two. Then the on-time train makes late zero, wiping it out, and the next early train changes nothing. The last two make it four, then one. Late should end at four, but it ends at one. So the corrected line is: set late to late plus one. Now late counts each late train. This explanation is by olevels.com, not an official mark scheme. The other three faults follow the same suspects. Line eight must stop at the last index. Line ten must use greater than zero, so on time is not late. Line twenty-three must work out the on-time trains. Check with the data. Four trains are late, two are early, and seven take away six leaves one on time.

Common mistake. A common mistake is writing only the changed part. The question asks for the line, so write it in full. Another mistake is using LENGTH as the last index. The last index is LENGTH minus one, so the loop must stop before LENGTH.

Your turn. Now you try. This algorithm should count the scores of fifty or more. It displays two, but the answer should be three. Give the line number of the error, and write the corrected line. Pause here and work it out.

Answer. Dry-run it. Sixty-two counts. Fifty is not greater than fifty, so it is not counted, but it should be. That is the first wrong row. The error is on line five. The corrected line is: if scores of i is greater than or equal to fifty, then. Now fifty is counted, and the output is three. Remember the method: know the expected result, dry-run to the first wrong row, then write the full fixed line and test it again. Now try the practice questions for this type.
