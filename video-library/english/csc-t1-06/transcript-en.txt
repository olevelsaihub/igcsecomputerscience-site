Think about a ticket machine at a station. It asks for your stop, decides the price, and then waits for the next person. It follows the same steps every time. On paper, we write steps like these as a flowchart or as pseudocode. A flowchart uses four shapes. A rounded box is start or stop. A parallelogram is input or output. A rectangle is a process, such as a calculation. A diamond is a decision. Every decision diamond has exactly two exits, labelled Yes and No. Every line has an arrow. A loop is an arrow that goes back up to an earlier step. In pseudocode, the same ideas are words. Here, count is set to zero before the loop. The loop reads five numbers. If a number mod three is zero, it divides exactly by three, so count goes up by one.

First, list the parts from the bullet points: the inputs, the decisions, what repeats, and the outputs. Each bullet usually earns a mark. Next, set starting values before any loop. Add one decision for each condition, in a sensible order, with both exits labelled. Then put each output on the right branch, close the loop, and make sure there is a path to Stop. Finally, test it with one value for each path.

Here is a real question from Paper 1 in June 2025. The user inputs a number n. If n is zero, the program stops. If it is positive, it shows Positive. If it is negative, it shows Negative. It repeats until zero is input. Draw a flowchart, for six marks. Draw Start in a rounded box, then a parallelogram: input n. Then a diamond: is n equal to zero? The Yes exit goes to Stop. From the No exit, draw a second diamond: is n greater than zero? Yes leads to output Positive. No leads to output Negative. From both outputs, draw arrows back up to input n. Now test it. Five: not zero, greater than zero, so Positive. Minus three: not zero, not greater than zero, so Negative. Zero: Yes at the first diamond, so Stop. Marks go to the start and input, each labelled decision, the two outputs on the right branches, the arrows and loop, and the correct symbols. This explanation is by olevels.com, not an official mark scheme.

A common mistake is a diamond with one exit, or with no Yes and No labels. Every decision needs two labelled exits. Another mistake is looping back to Start. That resets everything. Loop back to the input step instead.
