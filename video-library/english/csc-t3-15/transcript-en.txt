Idea. If you tell a friend there are five red cars in a row, you do not say red, red, red, red, red. You say five red. Run-length encoding uses exactly this idea to make data smaller. A run is a group of the same symbol, or the same pixel colour, sitting next to each other. RLE replaces each run with a count and the symbol. So four whites become four W. RLE works well when data has long runs, like a simple icon with big blocks of one colour. It works badly when values keep changing, and can even make the file bigger.

Method. Read the data left to right, one row at a time. Count how many of the same symbol appear before it changes. Write the count and the symbol, then start counting the next run. Finally, check each line. The counts must add up to the width of the row. If they do not, you have missed or doubled a pixel.

Worked example. Here is a real question from Paper 1 in November 2021. An icon is set out in an eight by eight grid of black and white pixels. Use run-length encoding to compress the first four lines. It is worth three marks. Here is the icon as a grid. Line one is white, white, white, black, then four whites. That is three W, one B, four W. Line two is one white, six black, one white. So one W, six B, one W. Line three changes a lot. One B, two W, one B, one W, one B, two W. Line four is three W, two B, three W. Here is the full answer, with every line checked against eight. All four lines correct earns three marks. This explanation is by olevels.com, not an official mark scheme.

Common mistake. A common mistake is counting all the whites in a line together. Line three has three separate white runs. Each run must be written on its own.

Answer. Row A is five W, two B, three W. That is six symbols instead of ten, so it is smaller. Row B has ten runs of one, so it becomes twenty symbols. That is bigger than the original. RLE suits row A, because it has long runs. Remember the method: read along each row, count each run, write count and symbol, and check the counts add up to the width.
