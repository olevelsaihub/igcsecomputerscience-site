Imagine finding your pencil in a messy bedroom, then in a tidy one. Code is the same. This program works, but what are a and b? What is it for? Another programmer would struggle to fix it. Here is the same program made readable. A comment says what it does. The names say what each value holds. Blank lines split the sections, and the print line is indented inside the if. So there are four techniques. Comments, which start with a hash sign and are ignored by the computer. Descriptive names, like total pay instead of t p. Indentation to show structure. And white space between sections. Indentation is more than tidiness. Moving lines in shows which lines belong inside a loop or an if. Here, Revise is indented, so it repeats three times. Exam is not, so it prints once, after the loop.

First, check whether the question wants a technique or a reason. A technique is something the programmer does. A reason is what it achieves for the reader. For a technique, name one from the list and add a tiny example if there is space. For a reason for comments, say how they help a person understand the code.

Here is a real question from Paper 2 in November 2021. Give one technique that programmers use to make their code easy to read and understand. It is worth one mark. The command word is give, and it wants a technique. So name an action the programmer takes. Pick one from the list: comments, descriptive names, indentation or white space. Write it in a few words with a small example. Give variables descriptive names, for example total pay instead of t p. That earns the mark. This explanation is by olevels.com, not an official mark scheme.

A common mistake is giving something that does not affect readability, like use correct code or use suitable data structures. Another mistake is saying comments make the program run faster. The computer ignores comments completely. They are only for people.

Now you try. Give one reason why programmers add comments to their code. Then give one other technique, not comments, that makes code easier to read. Pause here and work it out.

A, comments explain what a section of code does and how it works, so another programmer can understand it. B, use indentation to show which lines belong inside a loop or an if. Descriptive names or white space would also be right. Remember the method: decide if it is a technique or a reason, then give one clear idea with a small example.
