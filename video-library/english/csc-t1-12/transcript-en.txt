Think about making a cup of tea. You boil the water, put a tea bag in a cup, pour the water in, then wait. Each step is clear, and the order matters. A precise, ordered list of steps that solves a problem is called an algorithm. The same algorithm can be written down in four ways: as a flowchart, as pseudocode, as a written description in plain English, or as program code. A flowchart draws the steps as shapes joined by arrows. A rounded box is start or stop. A parallelogram is input or output. A rectangle is a process, and a diamond is a decision. You need no programming knowledge to follow it. Pseudocode looks like code, but it uses plain English words such as SET, WHILE and SEND. It is not tied to the exact rules, called the syntax, of any one language. Here, the loop makes three cups of tea. To test an algorithm, we use a trace table. It has a column for each variable and output. Each row shows the values as the algorithm runs. We fill it in by hand to follow the logic and find logic errors.

First, work out exactly what is being asked. Is it a definition, a feature, a benefit, or a choice of method for an audience? Each needs a different short answer. For a choice, name the method first. Then give a reason that fits the audience. The reason only scores if a suitable method has been named. In multiple choice, rule out options that are not ways of writing an algorithm. A truth table tests logic. A cipher is for encryption. A simulation models the real world.

Here is a real question from Paper 1 in June 2023. A programmer is showing a new algorithm to some non-technical managers. State a suitable method for writing it, and justify your answer. It is worth two marks. Start with the audience. The managers are non-technical, so they do not know any programming language. We need a method they can follow without code. A flowchart is the best choice. Each step is a shape, joined by arrows, so anyone can follow the order and the decisions. So the answer is: method, flowchart. Justification: it shows the steps visually with shapes and arrows, so the managers can follow it without knowing any code syntax. This explanation is by olevels.com, not an official mark scheme.

A common mistake is saying an algorithm is a program. A program is only one way to write an algorithm down. Another mistake is a reason that does not fit the audience. Saying pseudocode is close to real code does not help managers who cannot read code.

Now you try. A team of programmers will turn an algorithm into both Python and Java. State a suitable method for writing the algorithm, and justify your answer. Pause here and work it out.

The audience is programmers, so they can read code. Pseudocode suits them. It has the structure of code, but it is not tied to the syntax of one language, so it can be turned into Python or Java. Remember the method: decide who the audience is, name the method, then give a reason that fits them. Now try the practice questions for this type.
