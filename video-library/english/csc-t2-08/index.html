Syntax, logic and runtime errors

Think of following a recipe. If it is written in a language you cannot read, you cannot even start. If the oven breaks halfway, you stop. If it says salt instead of sugar, you finish, but the cake tastes wrong. Programs go wrong in the same three ways. A syntax error breaks the grammar rules of the language, so the program will not translate and never starts. Here, the if line is missing its colon. A runtime error happens while the program is running. An instruction cannot be carried out, such as dividing by zero, so the program crashes. A logic error is the sneaky one. The program runs to the end with no message, but the result is wrong. Here the subtraction is the wrong way round.

To classify an error, ask three questions in order. Does it translate? If not, it is a syntax error. Does it crash while running? Then it is a runtime error. Does it finish with the wrong answer? Then it is a logic error. In a tick table, each description matches exactly one error type. So put one tick in each row, never two.

Here is a real question from Paper 2 in June 2025. Complete the table by ticking the error type for each of three descriptions. It is worth three marks. Row one: the program does not produce the expected output. It ran, so it is not syntax. It did not crash, so it is not runtime. It is a logic error. Row two: the program does not translate. It broke a rule of the language, so it is a syntax error. Row three: the program crashes during execution. Execution means running, so it is a runtime error. One mark for each correct tick. This explanation is by olevels.com, not an official mark scheme.

A common mistake is calling divide by zero a logic error. It makes the program crash, so it is a runtime error. Another mistake is calling a wrong-way-round subtraction a syntax error. The code follows every rule, so it is a logic error.

Now you try. Name the error type for each fault. A, a misspelt keyword, prnt instead of print. B, a loop that adds one too few numbers. C, asking for item ten in a list of five items. Pause and decide.

A is a syntax error, because a misspelt keyword breaks the language rules. B is a logic error, because the program runs but the total is wrong. C is a runtime error, because using an index outside the list crashes the program. Remember the method: will it translate, does it crash, or is the answer wrong? One question finds the error type every time. Now try the practice questions for this type.
