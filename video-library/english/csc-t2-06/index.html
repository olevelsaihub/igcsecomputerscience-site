Idea. Think about your morning. You get up, wash, then get dressed, in order. That is sequence. If it is raining, you take an umbrella. That is selection. You keep brushing your teeth until they are clean. That is iteration. Selection means the program chooses a path using a condition. In pseudocode it starts with IF. If rain is TRUE, one message is shown. Otherwise, the ELSE message is shown. In a flowchart, look at the arrows. A decision diamond whose paths both carry on down is selection. If an arrow goes back up to an earlier step, the steps repeat. That is iteration, also called a loop. There are three kinds of loop. A count-controlled loop, FOR, repeats a fixed number of times. A pre-conditioned loop, WHILE, tests first, so it may run zero times. A post-conditioned loop, REPEAT UNTIL, tests last, so it always runs at least once.

Method. First, look for the keyword or the shape. IF, or a diamond with no loop back, is selection. FOR, WHILE, REPEAT, or an arrow going back up, is iteration. For the kind of loop, check where the condition is. FOR is count-controlled. WHILE at the top is pre-conditioned. UNTIL at the bottom is post-conditioned. For a why this loop question, find what makes the loop stop. Then give the benefit, and link it to that stopping condition with because.

Worked example. Here is a real question from Paper 1 in June 2025. Lines ten to fifteen use a post-conditioned loop. Explain one reason why it is better than a count-controlled loop. It is worth two marks. Each pass adds one to testNum, then checks whether testNum divides the number exactly. If the remainder is zero, flag becomes TRUE. The loop stops when testNum reaches the number, or when flag is TRUE. Try number equals nine. Pass one: testNum is two, and nine mod two is one, so flag stays FALSE. Pass two: testNum is three, and nine mod three is zero, so flag becomes TRUE. The loop stops after only two passes. A count-controlled loop from two to nine would always make eight passes, even after the answer is known. That is six wasted passes. So the answer is: it is more efficient, because the loop ends as soon as a factor of the number is found, while a count-controlled loop would keep going. This explanation is by olevels.com, not an official mark scheme.

Common mistake. A common mistake is calling a WHILE loop count-controlled because it uses a counter. It tests a condition, so it is condition-controlled. Another mistake is a benefit with no link to the algorithm. Say what makes this loop stop early.
