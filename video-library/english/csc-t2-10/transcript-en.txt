When you sign up to a website, it might refuse a phone number with letters in it, before you even press send. That automatic check of the rules is called validation. Validation can only check that data is sensible and allowed. It cannot prove the data is actually correct. A valid but wrong phone number still gets through. There are four kinds of check to know. A length check counts the characters. A format check tests the kind of character in each position. A range check tests a number is between limits. A check character is worked out from the rest of the code.

First, split the format into its parts: the length, each group of positions, and any check character. Cross out any test the question already gives you. Then build the erroneous data. Start from a valid code and change only the feature your test checks. Re-check every other rule, so the code fails that one test only.

Here is a real question from Paper 2 in November 2020. Each stock code has ten characters. Characters one to three are upper-case letters. Four to nine are digits from one to nine. Character ten is e if the digits add to an even number, or o if odd. The last-character test is given, so we write two others. Test one: are characters one to three upper-case letters? Start from the valid code W A S one two three four five six o. The digits add to twenty-one, which is odd, so o is right. Now make only the letters wrong: capital W, then small a s. The length is still ten, the digits still add to twenty-one, and o is still right. Only the case fails. Test two: are characters four to nine all digits from one to nine? Take W A S one one one one one one e. Changing a one to a zero makes the sum five, which is odd. So the last letter must change to o, or two rules would fail.

The most common mistake is giving data that breaks two rules at once, such as the wrong length and the wrong case. It must fail only its own test. Another mistake is forgetting that changing a digit can change the check character, or writing a vague test like, is it valid?

Now you try. A ticket code has seven characters. One and two are upper-case letters. Three to six are digits from one to nine. Seven is e if the digits add to an even number, or o if odd. T K two four five seven e is valid. Write a test for characters three to six, and data that fails only that test. Pause here and work it out.

The test is: are characters three to six all digits from one to nine? Change the two to a zero. The digits now add to sixteen, which is still even, so e stays correct. T K zero four five seven e fails only that test. Remember the method: split the format into rules, write one precise test per rule, then change one feature of a valid code and re-check the rest.
