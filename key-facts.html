Key facts by topic

1 Problem solving

What algorithms are and how we write them down
  • An algorithm is a precise, ordered list of steps that solves a problem or carries out a task.
  • An algorithm can be written as a flowchart, as pseudocode, as a written description in plain English, or as program code.
  • A flowchart is visual and needs no programming knowledge, so it suits a non-technical audience.
  • Pseudocode looks like simple code written with English words but is not tied to the syntax (exact rules) of one language.
  • A trace table has a column for each variable or output and rows that show how the values change as the algorithm runs.
  • Trace tables are filled in by hand to test an algorithm, follow how it works, and find logic errors.
  • A truth table tests logic, and a cipher is a method of encryption; neither is a way of writing an algorithm.

Bubble sort, one pass at a time
  • A bubble sort puts a list in order by comparing each pair of neighbouring items and swapping them if they are in the wrong order.
  • One pass means going through the whole list once, from the first pair to the last pair.
  • After the first pass of an ascending sort, the largest item has 'bubbled' to the end; after the second pass, the two largest are in place.
  • The sort stops after a pass in which no swaps happen; that final checking pass still counts as a pass.
  • Bubble sort sorts in place: it only needs one extra variable to hold a value during a swap.
  • Ascending means smallest to largest; descending means largest to smallest; for words, alphabetical order is used.

Decomposition and abstraction
  • Computational thinking is a set of problem-solving skills used before and while writing programs; decomposition and abstraction are two of them.
  • Decomposition means splitting a big problem into smaller sub-problems that can each be solved, coded and tested separately.
  • Planning comments such as '// roll dice 3 times' and '// calculate final score' are decomposition: each comment is one smaller task.
  • Abstraction means hiding or leaving out the details that do not matter, so you can focus on what does.
  • Using a library subprogram (such as a random number function) is abstraction: you use what it returns without needing to know how it works inside.
  • A model of the real world (such as a dice game) is an abstraction because it keeps only the features the program needs.

Merge sort: split, then merge
  • Merge sort is a divide and conquer algorithm: it splits a problem into smaller parts, solves them, then combines the results.
  • The list is split in half again and again until every list holds just one item.
  • A list with one item is already sorted.
  • Merging takes two sorted lists and builds one sorted list by repeatedly taking the smaller (or larger, for descending) front item.
  • Merging goes in stages: single items into pairs, pairs into fours, and so on until one list remains.
  • Merge sort needs extra memory for the new lists it creates, unlike bubble sort, which sorts in place.

Compare sorts and searches
  • A linear search checks items one by one from the first until it finds the target or reaches the end of the list.
  • A linear search works on sorted or unsorted lists and is simple to write.
  • A binary search needs a sorted list but halves the search area with each comparison, so it needs far fewer comparisons on a large list.
  • For 1000 sorted items, a binary search needs at most 10 comparisons; a linear search may need all 1000.
  • Bubble sort sorts in place, so it uses very little extra memory (one temporary variable for swaps), but it is slow on large lists.
  • Merge sort is usually much faster on large lists, but it needs extra memory to hold the split and merged lists.
  • Choosing an algorithm depends on the data: its size, whether it is sorted, and how much memory is available.

Make an algorithm faster or work for any amount of data
  • An efficient algorithm does the job with fewer steps, such as fewer comparisons, or with less memory.
  • Nested IF ... ELSE stops testing as soon as one condition is True; a list of separate IF statements always tests every condition.
  • Hard-coding means writing a fixed value (such as 8 for the number of items) into the code; it breaks when the data size changes.
  • LENGTH(array) gives the number of items in an array, so a loop such as WHILE i < LENGTH(flavours) works for any size of list.
  • An array stores many values under one name with an index, so one loop can replace many separate variables and IF statements.
  • Generality means the algorithm still works when the amount or values of data change, without rewriting the code.

Say what an algorithm (or one line) does
  • The purpose of an algorithm is the job it does for the user, said in plain words (for example: reverses a list, checks whether a number is prime).
  • The best way to find the purpose is to dry-run it with a tiny example and compare what goes in with what comes out.
  • A temporary variable (often called temp) holds one value during a swap, because copying a over b would otherwise lose b's old value.
  • Adding 1 to an index or counter moves the algorithm to the next item; without it a loop could repeat for ever (an infinite loop).
  • A FOR loop that counts from LENGTH(list) - 1 down to 0 with STEP -1 visits the items from last to first.
  • A test can be redundant: if an earlier IF has already limited the possible values, a later IF that checks the only remaining value is not needed.
  • A subprogram is a named block of code that can be called; its purpose is described by what it returns or outputs for its parameters.

Binary search step by step
  • A binary search only works on a list that is already sorted.
  • It looks at the middle item first: midpoint = (low + high) DIV 2, where DIV keeps only the whole-number part.
  • If the target is smaller than the middle item, the upper half is discarded (high = mid - 1); if larger, the lower half is discarded (low = mid + 1).
  • It repeats on the remaining half until the item is found or the search range is empty (low is greater than high).
  • Each comparison halves the part still to be searched, so it is a divide and conquer algorithm.
  • The most items examined for a list of n items is the number of times n can be halved, plus one; for 5 items this is 3.
  • On an unsorted list, discarding a half can throw away the target, so the search can miss an item that is there.

Trace tables: run the algorithm by hand
  • A trace table is a grid with one column for each variable (and often one for outputs) and one new row each time a value changes.
  • Dry-running means following an algorithm line by line with real input values, exactly as the computer would, without guessing.
  • SET x TO 5 in Pearson pseudocode is the same as x = 5 in Python: the old value of x is replaced.
  • A variable keeps its value until a line changes it, so you only write a new value when it actually changes.
  • A WHILE loop tests its condition before each run of the body; a REPEAT ... UNTIL loop runs the body first and tests at the end.
  • MOD gives the remainder after division (7 MOD 2 = 1) and DIV gives the whole-number part (7 DIV 2 = 3); in Python these are % and //.
  • In a flowchart, a diamond is a decision with a Yes and a No exit; follow only the exit that matches the current values.
  • Outputs (SEND ... TO DISPLAY, print or a parallelogram box) are written in the output column at the moment they happen, with the exact text and value.

Write an algorithm on paper: flowcharts and pseudocode
  • Every algorithm is built from three constructs: sequence (steps in order), selection (choosing a path with IF or a decision) and iteration (repeating with a loop).
  • Flowchart symbols: a rounded box (terminator) for Start and Stop, a parallelogram for input or output, a rectangle for a process, and a diamond for a decision.
  • Every decision diamond has exactly two exits, labelled Yes and No (or True and False).
  • Arrows show the order of steps; a loop is drawn as an arrow going back up to an earlier step.
  • In pseudocode, a counter is set to 0 before a loop (SET count TO 0) and increased inside it (SET count TO count + 1).
  • Text is joined to a value with & in Pearson pseudocode, e.g. SEND "There are " & count & " vowels" TO DISPLAY; in Python you can use + with str() or a comma in print().
  • A remainder of 0 shows divisibility: number MOD 3 = 0 means the number divides exactly by 3 (number % 3 == 0 in Python).

Find and fix errors in an algorithm
  • A logic error lets the algorithm run but gives the wrong result; a syntax error breaks the rules of the language so it cannot run.
  • An off-by-one error is a loop or test that goes one step too far or stops one step too early (for example > instead of >=).
  • Array indexes start at 0, so the last index of an array is LENGTH(array) - 1; reading index LENGTH(array) is out of range.
  • A counter must be increased with SET count TO count + 1; SET count TO value replaces it instead of counting.
  • A sentinel value (such as -1 meaning 'stop') must not be added into totals or counted as data.
  • A WHILE loop that searches an array needs two stop conditions joined with AND: not yet found, and index still inside the array.
  • A trace table with test data is the standard way to show where an algorithm first goes wrong.
  • A corrected line should keep the same pseudocode style and change only what is wrong.

2 Programming

Make code easy to read
  • Readable code is code that another programmer can quickly understand and fix.
  • A comment is a note for humans that the computer ignores; in Python it starts with #.
  • Comments explain what a section of code does and how it works.
  • Descriptive (meaningful) names, like totalPay instead of tp, show what a variable, constant or subprogram is for.
  • Indentation means moving lines in from the margin to show which lines belong inside a loop, IF or subprogram.
  • White space (blank lines and spaces) separates sections so code is not crammed together.
  • Readable code is easier to maintain, debug and update later.

Local and global variables
  • The scope of a variable is the part of the program where it can be used.
  • A global variable is created in the main program, at the top level, outside any subprogram.
  • A global variable can be read from anywhere in the program.
  • A local variable is created inside a subprogram (a def block in Python).
  • A local variable can only be used inside the subprogram where it was created.
  • A local variable disappears when its subprogram finishes, which frees its memory.
  • Parameters behave like local variables: they only exist inside their subprogram.
  • Two subprograms can each have a local variable with the same name without clashing.

Pick the right data type for a value
  • A data type tells the computer what kind of value a variable holds and what can be done with it.
  • An integer is a whole number with no decimal part, such as 19, 0 or -7.
  • A real number has a decimal part, such as 4.5 or 18.75; in Python this type is called float.
  • A Boolean can hold only two values: True or False.
  • A char is one single character, such as 'A', '7' or '?'; Python stores it as a string of length one.
  • A string is a sequence of characters, such as "Hello" or "AB12"; it is written inside quotation marks.
  • If a calculation multiplies or divides using a real number, the answer is also a real number (0.5 * time gives a float).
  • Money with pence, like 356.25, is stored as real; a count of hours like 19 is stored as integer.
  • True is a Boolean value, not a string, unless it is written inside quotation marks.

Syntax, logic and runtime errors
  • A syntax error breaks the grammar rules of the language, so the program will not translate (will not start running).
  • Examples of syntax errors in Python: a missing colon after if, a misspelt keyword, or writing x instead of * to multiply.
  • A logic error lets the program run, but it gives the wrong result or behaves in an unintended way.
  • Examples of logic errors: subtracting the wrong way round, or using > where >= was needed.
  • A runtime error happens while the program is running and makes it crash or stop unexpectedly.
  • Examples of runtime errors: dividing by zero, using an index outside an array, or opening a file that does not exist.
  • To classify an error, ask: does it translate? Does it crash? Does it give the wrong answer?

Variables, constants, arrays and records
  • A variable is a named memory location whose value can change while the program runs.
  • A constant is a named memory location whose value stays fixed while the program runs; in Python we show this by writing the name in capitals, like TAX = 0.05.
  • Using a constant means a value is typed in one place only, so updating it later means changing just one line.
  • In pseudocode a CONST can only be set once; Python does not enforce this, so capital letters are a convention that tells programmers not to change the value.
  • A constant with a clear name, like VAT_RATE, makes code easier to read than a bare number like 0.2.
  • An array holds many values of the same data type under one name; each value is reached by its index, starting at 0.
  • A one-dimensional array is like a single list or row; a two-dimensional array is like a table with rows and columns.
  • A record groups related fields about one item, and the fields can be different data types (for example a name, a year and a price).
  • A variable holds one value at a time, whereas an array holds a whole collection of values.

Spot constructs, operators, keywords and comments
  • A comment in Python starts with # and runs to the end of the line; the computer ignores it.
  • Logical operators in Python are and, or, not (AND, OR, NOT in pseudocode).
  • Relational operators compare values: ==, !=, <, >, <=, >= in Python; =, <>, <, >, <=, >= in pseudocode.
  • Selection starts at the line with if (IF in pseudocode).
  • Iteration starts at the line with for or while (FOR, WHILE, REPEAT in pseudocode).
  • A subprogram definition starts at the line with def (FUNCTION or PROCEDURE in pseudocode).
  • Initialising a variable means giving it its first value, e.g. count = 0.
  • User input in Python uses input(); in pseudocode it is RECEIVE ... FROM KEYBOARD.
  • A data structure is initialised where a list is first set up, e.g. vowels = ["a", "e", "i", "o", "u"].
  • Arithmetic operators do maths: + add, - subtract, * multiply, / divide, % modulus (remainder) and // integer division in Python.

Functions, procedures, parameters and libraries
  • A subprogram is a named block of code that does one job and can be called (run) from other parts of the program.
  • A function is a subprogram that always sends a value back to the code that called it, using return.
  • A procedure is a subprogram that carries out a task but does not have to return a value.
  • Functions and procedures can both take parameters, use local variables and be reused many times.
  • A parameter is a named input listed in the subprogram's header, e.g. def area(pLength, pWidth):
  • Parameters let the same subprogram work with different data each time it is called, so it is reusable.
  • A built-in subprogram comes ready-made with the language, such as print(), len(), int() and input() in Python.
  • A library is a collection of pre-written subprograms that can be imported, e.g. import random.
  • Library code has already been tested, so it saves the programmer time and is less likely to contain errors.

Find named items in a program
  • An identifier is the name given to a variable, constant, array or subprogram.
  • A parameter is a name inside the brackets of a subprogram header, e.g. inSales in def getWages(inSales, inAge):
  • An argument is the value or variable passed in the brackets when the subprogram is called, e.g. sales in getWages(sales, age).
  • The variable on the left of x = someFunction(...) receives the value returned by the function.
  • A user-written subprogram is one defined in the program with def (FUNCTION or PROCEDURE in pseudocode).
  • A built-in subprogram comes with Python, e.g. print, input, int, float, len.
  • A variable created inside a def block is local; one created in the main program is global.

  • A variable's data type comes from its value: float(input(...)) or 0.0 gives a real; str or text in quotes gives a string.

Normal, boundary and erroneous test data
  • Test data is input chosen to check that a program works properly.
  • Normal data is a typical valid value that the program should accept, well inside the allowed range.
  • Boundary data is a value at the very edge of the valid range, such as the smallest or largest value allowed.
  • Erroneous data is invalid data that the program should reject, such as a value outside the range or the wrong data type.
  • For a range of 1 to 12 inclusive: normal could be 6, boundary 1 or 12, erroneous 0, 13 or 'abc'.
  • For a text field allowed 2 to 8 letters: a 2-letter or 8-letter word is boundary; 1 letter or 9 letters is erroneous.
  • Some papers accept the value just outside the range as boundary data; always read the definition given in the question.
  • Each test example in a table should be different.

Spot selection and iteration, and pick the right loop
  • Sequence means instructions run one after another in order.
  • Selection means the program chooses a path using a condition: IF ... THEN ... ELSE (if/elif/else in Python).
  • Iteration means repeating a block of code; it is also called a loop.
  • In a flowchart, a decision diamond with no arrow going back up is selection; an arrow looping back is iteration.
  • A count-controlled loop repeats a fixed number of times: FOR in pseudocode, for in Python.
  • A pre-conditioned loop checks its condition before each pass and may run zero times: WHILE in pseudocode and Python.
  • A post-conditioned loop checks its condition after each pass, so it always runs at least once: REPEAT ... UNTIL in pseudocode.
  • A condition-controlled loop can stop as soon as its job is done, which avoids wasted passes.
  • The keyword if starts selection; for and while start iteration.

Design validation checks for a code format
  • Validation is an automatic check that input data follows set rules before it is accepted.
  • Validation checks whether data is sensible and allowed; it cannot prove the data is actually correct.
  • A length check tests the number of characters, e.g. len(code) == 10 in Python.
  • A format (pattern) check tests the kind of character at each position, e.g. letters first, then digits.
  • A range check tests that a number lies between limits, e.g. 1 to 9.
  • A check-character test recalculates a character from the rest of the code and compares it.
  • Good erroneous data for a check breaks only that one rule and obeys all the other rules.

3 Data

What encryption is and why we use it
  • Plaintext is a readable message before it is encrypted.
  • Ciphertext is the scrambled, unreadable message after encryption.
  • Encryption turns plaintext into ciphertext using an algorithm and a key.
  • Decryption turns ciphertext back into plaintext using the key.
  • Encryption is used so that only the intended receiver, who has the key, can understand the data.
  • Encryption does not stop data being intercepted or stolen; it stops thieves understanding it.
  • Encryption does not stop hackers getting into a network and does not make files smaller.

Binary to denary and back (unsigned, 0 to 255)
  • Binary is base 2: each digit (a bit) is either 0 or 1.
  • Denary is our everyday base 10 number system.
  • In an 8-bit number the place values, from left to right, are 128, 64, 32, 16, 8, 4, 2 and 1.
  • Unsigned means the number has no sign, so it is always zero or positive.
  • With 8 unsigned bits you can store whole numbers from 0 (00000000) to 255 (11111111).
  • A nibble is a group of 4 bits; a byte is 8 bits, or two nibbles.
  • To change binary to denary, add up the place values that sit under each 1.
  • To change denary to binary, take away the biggest place value that fits, write a 1 there, and repeat with what is left.
  • If the bit on the far right (worth 1) is 0, the number is even; if the far-left bit (worth 128) is 1, the number is at least 128.

Hexadecimal: why we use it and how to convert
  • Hexadecimal (hex) is base 16.
  • Hex uses the digits 0 to 9 and then the letters A to F for the values 10 to 15.
  • A = 10, B = 11, C = 12, D = 13, E = 14, F = 15.
  • One hex digit stands for exactly one nibble (4 bits), because 4 bits give 16 patterns.
  • So one byte (8 bits) is always written as two hex digits.
  • Nibble place values are 8, 4, 2, 1.
  • Denary values from 0 to 15 become a single hex digit.
  • Hexadecimal is base 16; denary is base 10; binary is base 2.
  • Hex digits are 0-9 and A-F.
  • One hex digit matches one nibble (4 bits) because 2 to the power 4 is 16.

Pixels, resolution and colour depth
  • A bitmap image is made of a grid of tiny squares called pixels.
  • A pixel (picture element) is the smallest part of a bitmap image; each pixel has one colour.
  • Resolution describes how much detail there is: often given as width x height in pixels, or as pixels per inch (ppi), pixels per centimetre or dots per inch (dpi).
  • Colour depth is the number of bits used to store the colour of each pixel.
  • More colour depth means more possible colours (2^n) but more bits for every pixel.
  • File size grows with the number of pixels and with the colour depth.
  • Image file size in bits = width x height x colour depth (before any metadata or compression).

ASCII and Unicode character sets
  • A character set gives every character (letter, digit, symbol) its own binary code.
  • Standard ASCII uses 7 bits per character, so it has 2^7 = 128 codes (0 to 127).
  • ASCII covers English letters, digits, punctuation and some control codes.
  • Codes for letters and digits run in order: if 'A' is 65 then 'H' is 65 + 7 = 72.
  • Unicode is a much larger character set than ASCII. Its encodings use more bits for many characters: UTF-16 uses 16 or 32 bits per character, and UTF-8 uses 8 to 32 bits (8 for the ASCII characters).
  • Unicode can represent the characters of almost every language, plus symbols and emoji.
  • ASCII uses less storage per character than Unicode, and it is a widely agreed standard.
  • The first 128 Unicode codes are the same as ASCII.

How many patterns from n bits
  • Each extra bit doubles the number of different patterns.
  • n bits can make 2 to the power n different patterns (2^n).
  • 1 bit gives 2, 2 bits give 4, 3 bits give 8, 4 bits give 16, 8 bits give 256.
  • Colour depth is the number of bits used for each pixel; 2^n colours are possible with n bits.
  • Bit depth in sound is the number of bits per sample; 2^n levels are possible.
  • To find the minimum bits for k items, find the smallest n where 2^n is at least k.
  • With n bits, unsigned values run from 0 to 2^n - 1.
  • Every item must get its own different code, and all codes should be the same length.

Pigpen cipher
  • The Pigpen cipher is a substitution cipher: each letter is replaced by a symbol.
  • The key is a set of grids: usually two noughts-and-crosses grids and two X shapes, one of each with dots.
  • A letter's symbol is the shape of the lines around its cell, plus a dot if the letter is in a dotted grid.
  • In the usual layout, A to I are in the plain grid, J to R in the dotted grid, S to V in the plain X and W to Z in the dotted X.
  • To decode, match each symbol's shape and dot to a cell in the grid and read its letter.
  • A valid Pigpen key gives every letter a symbol, and no two letters share the same symbol.

Adding binary numbers and overflow
  • Binary addition works column by column from the right, like denary addition.
  • The rules are: 0 + 0 = 0; 0 + 1 = 1; 1 + 1 = 10 (write 0, carry 1); 1 + 1 + 1 = 11 (write 1, carry 1).
  • A register is a small store inside the processor that holds a fixed number of bits, for example 8.
  • Overflow happens when the result of a calculation is too big to fit in the bits available.
  • In 8-bit addition, overflow shows up as a carry out of the leftmost column, which would need a ninth bit.
  • The extra bit is lost, so the stored result is wrong.
  • Overflow can make a program give wrong results or crash.
  • Check your sum by converting both numbers and the answer to denary.

Caesar cipher
  • A Caesar cipher shifts every letter the same number of places along the alphabet.
  • The shift is the key; a positive shift moves forward (A to D for +3) and a negative shift moves back.
  • The alphabet wraps round: after Z comes A again, and before A comes Z.
  • To decrypt, apply the opposite shift.
  • Two shifts in a row add together: -6 then +8 is the same as +2.
  • There are only 25 useful shifts, so an attacker can try them all quickly (a brute-force attack).
  • Letter frequency (for example E is the most common English letter) can also reveal the shift.

Compression: lossy or lossless?
  • Compression means making a file smaller.
  • Smaller files take less storage space and are faster to send over a network.
  • Lossy compression permanently removes some data, so the original can never be rebuilt exactly; examples are JPEG and MP3.
  • Lossy compression usually gives much smaller files, and people often cannot notice the missing detail in pictures or music.
  • Lossless compression shrinks the file without losing any data, so the original can be rebuilt exactly; examples are PNG and run-length encoding.
  • Lossless files are usually bigger than lossy ones.
  • Text, documents and program code must use lossless compression, because losing any character changes the meaning.
  • Drawbacks of compression include the time to compress and decompress and the need for compatible software.

Kilobytes and kibibytes
  • Decimal (SI) prefixes go up in steps of 1000: 1 kilobyte (kB) = 1000 bytes, 1 megabyte (MB) = 1000 kB.
  • Binary (IEC) prefixes go up in steps of 1024: 1 kibibyte (KiB) = 1024 bytes, 1 mebibyte (MiB) = 1024 KiB.
  • 1000 is 10^3 (base 10); 1024 is 2^10 (base 2).
  • So a kibibyte is slightly bigger than a kilobyte.
  • To convert, change to bytes with one factor, then divide by the other factor.
  • Example: 500,000 bytes = 0.5 MB, but 500 KiB = 512,000 bytes.
  • SI is the International System of Units; IEC is the International Electrotechnical Commission.

Run-length encoding (RLE)
  • Run-length encoding is a lossless compression method.
  • A run is a group of the same symbol (or pixel colour) next to each other.
  • RLE replaces each run by a count and the symbol, for example WWWW becomes 4W.
  • Use the same order (count then symbol, or symbol then count) all the way through.
  • RLE works well when the data has long runs, such as simple images with large areas of one colour.
  • RLE works badly when values rarely repeat; it can even make the file bigger, because each single value gains a count.
  • Decoding RLE gives back exactly the original data.

Sign and magnitude numbers
  • A signed integer is a whole number that can be positive or negative.
  • In sign and magnitude, the leftmost bit (the most significant bit, MSB) is the sign bit.
  • A sign bit of 0 means positive; a sign bit of 1 means negative.
  • The other 7 bits hold the magnitude, which is the size of the number without its sign.
  • The 7 magnitude bits have place values 64, 32, 16, 8, 4, 2, 1.
  • In 8 bits the range is -127 (1111 1111) to +127 (0111 1111).
  • Sign and magnitude has two patterns for zero: 0000 0000 and 1000 0000.
  • To write a negative number, convert its size to 7 bits and put a 1 in front.

Logical and arithmetic binary shifts
  • A binary shift moves every bit left or right by a given number of places.
  • Bits that move off the end are lost.
  • In a logical shift, the empty places are always filled with 0s.
  • In an arithmetic right shift, the empty places on the left are filled with copies of the sign bit (the leftmost bit), so a negative number stays negative.
  • An arithmetic left shift fills the empty places on the right with 0s, like a logical left shift.
  • Each shift of one place left multiplies an unsigned number by 2; each shift right divides it by 2 (any remainder is lost).
  • Shifting right by 2 divides by 4; shifting right by 3 divides by 8.
  • Pearson's papers describe an arithmetic shift as one that keeps the sign of the number: on a right shift the sign bit is copied into the empty places; answer in those terms.

Rail Fence cipher
  • The Rail Fence cipher is a transposition cipher: the letters stay the same but their order changes.
  • The key is the number of rails (rows).
  • Write the message diagonally down the rails, then back up, in a zig-zag, one letter per column.
  • Read the ciphertext off one rail at a time, from the top rail to the bottom, left to right.
  • To find the key from a diagram, count the rails.
  • It is weak because there are only a few sensible keys, so an attacker can try each one (brute force).

Sound sampling: analogue to digital
  • Sound in the real world is an analogue signal: a smooth wave that changes continuously.
  • A computer stores sound as a digital signal: a list of separate binary numbers.
  • Sampling means measuring the amplitude (height) of the sound wave at regular time intervals.
  • Each measurement (sample) is stored as a binary number.
  • Sampling frequency (sample rate) is the number of samples per second, measured in hertz (Hz).
  • Bit depth is the number of bits used for each sample.
  • A higher sampling frequency or bit depth gives a closer copy of the original sound but a larger file.
  • On a sound graph the x-axis is time (seconds) and the y-axis is amplitude.

Two's complement numbers
  • Two's complement is the usual way computers store signed (positive or negative) whole numbers.
  • In 8-bit two's complement the leftmost bit has a place value of -128; the others are 64, 32, 16, 8, 4, 2, 1 as normal.
  • If the leftmost bit is 1 the number is negative; if it is 0 the number is positive.
  • The 8-bit range is -128 (1000 0000) to +127 (0111 1111).
  • There is only one pattern for zero, 0000 0000.
  • To make a negative number: write the positive version in 8 bits, flip every bit (0 to 1, 1 to 0), then add 1.
  • Negating means changing the sign but keeping the size; flip-and-add-1 works in both directions.
  • A quick way to read a negative pattern: start at -128 and add the place values of the other 1s.

Vigenere cipher
  • The Vigenere cipher uses a keyword to give a different Caesar shift to each letter.
  • The keyword is written again and again under the message until every letter has a keyword letter.
  • In the Vigenere square, each row starts with a different letter: row a is no shift, row b is shift 1, and so on.
  • To encrypt: find the keyword letter's row and the plaintext letter's column; the letter where they meet is the ciphertext.
  • To decrypt: go to the keyword letter's row, find the ciphertext letter in that row, and read the letter at the top of its column.
  • Using numbers (a=0 ... z=25): ciphertext = (plain + key) mod 26 and plain = (cipher - key) mod 26.
  • Because the shift keeps changing, Vigenere is harder to crack than a Caesar cipher.

Expressions for file size and transfer time
  • Image size in bits = width (pixels) x height (pixels) x colour depth (bits per pixel).
  • Sound size in bits = sample rate (samples per second, Hz) x bit depth (bits per sample) x length (seconds).
  • Text size in bytes = number of characters x bytes per character.
  • Divide bits by 8 to get bytes; multiply bytes by 8 to get bits.
  • Metadata (data about the file, such as its size and date) is added on, in bytes, after converting to bytes.
  • Decimal units step by 1000: kB = 1000 bytes, MB = 1000 x 1000 bytes, GB = 1000^3 bytes.
  • Binary units step by 1024: KiB = 1024 bytes, MiB = 1024 x 1024 bytes.
  • Transmission time (s) = file size in bits / transmission speed in bits per second; Mbps means millions of bits per second.
  • 'Construct an expression' means write the calculation, with brackets so the order is clear; you do not have to work it out.

Hardware devices: input, output and how they connect
  • Hardware is the physical parts of a computer that you can touch.
  • Software is the set of instructions (programs) that tells the hardware what to do.
  • A computer needs both: hardware cannot do anything useful without instructions, and software needs hardware to run on.
  • An input device sends data into the computer, for example a mouse, keyboard or microphone.
  • An output device receives data from the computer and presents it, for example a speaker, printer or screen.
  • Some devices do both jobs, for example a touch screen, a headset with a microphone, or a USB storage device.
  • On a diagram, an arrow shows the direction data travels: towards the CPU for input, away from the CPU for output, both ways for a device that does both.
  • A smartphone's built-in output devices include its screen, speaker and vibration motor.

Utility software: anti-malware, defrag and file tools
  • Utility software is system software that helps maintain, protect or tidy up a computer.
  • Anti-malware protects against harmful software; types include antivirus, anti-spyware, anti-adware and a software firewall.
  • Anti-virus programs can detect viruses by scanning, quarantine infected files, remove them, scan in real time and update themselves.
  • Over time, a file's blocks can become scattered across a hard drive; this is called fragmentation.
  • A defragmentation utility moves each file's blocks next to each other in order and gathers the free space together.
  • Defragmenting a hard drive makes files quicker to read because the head moves less.
  • A file repair or recovery utility tries to fix corrupt files; a backup utility makes copies so files can be restored after damage.
  • A file conversion utility changes a file from one format to another, such as JPEG to PNG.

Complete a truth table
  • A truth table lists every possible combination of inputs and shows the output for each one.
  • In logic, 1 means true and 0 means false.
  • With 2 inputs there are 4 rows; with 3 inputs there are 8 rows (2 to the power of the number of inputs).
  • List input rows in binary counting order: 000, 001, 010, 011, 100, 101, 110, 111.
  • AND gives 1 only when both inputs are 1.
  • OR gives 1 when at least one input is 1.
  • NOT flips the value: NOT 1 = 0 and NOT 0 = 1.
  • Work out brackets and NOT columns first, then combine those columns to get the final column.

Embedded systems: small computers inside devices
  • An embedded system is a small computer built into a larger device to do one specific job.
  • Examples include the controllers in washing machines, smartwatches, ticket machines and TV remote controls.
  • Embedded systems have both hardware and software, with the software usually set by the manufacturer and not changed by the user.
  • They are often small, cheap to mass produce, low power and robust.
  • They usually have built-in memory (often flash) and a simple or no user interface.
  • Many use sensors to measure the world (for example temperature, water level, heart rate) and actuators such as motors to act on it.
  • Because they do one job, their processor, memory and power use can be chosen to be just enough for that job.
  • Many embedded systems work in real time, responding straight away to inputs.

How hard drives, optical discs and SSDs store data
  • Secondary storage keeps data permanently, even when the power is off.
  • A magnetic hard disc drive (HDD) stores data on spinning discs called platters, divided into tracks and sectors.
  • In an HDD, a read/write head on a moving arm reads and changes tiny magnetised areas; one magnetic direction (polarity) is 1, the other is 0.
  • Optical discs (CD, DVD) store data as pits and lands on a spiral track, read by a laser.
  • Light reflects differently from pits and lands, and the changes in reflection are read as 1s and 0s.
  • A solid state drive (SSD) uses flash memory chips with no moving parts.
  • In an SSD, transistors trap electrical charge; whether a cell holds charge represents a 0 or a 1, and the charge stays without power.
  • Compared with an HDD, an SSD is faster, quieter, lighter, uses less power and is tougher because it has no moving parts.

RAM, ROM, virtual memory and flash memory
  • RAM (random-access memory) holds the programs and data the computer is using right now.
  • RAM is volatile: its contents are lost when the power is switched off.
  • ROM (read-only memory) is non-volatile and its contents cannot normally be changed.
  • ROM stores start-up instructions, such as the BIOS or firmware that boots the computer.
  • Virtual memory is space on secondary storage (hard disc or SSD) used as extra RAM when RAM is full.
  • With virtual memory, data not being used is moved out of RAM to the disc, and moved back when it is needed again.
  • Flash memory is non-volatile memory that can be written and rewritten; it is used in SSDs and memory cards.
  • A computer needs RAM for running programs and ROM to start up, because RAM is empty when the power comes on.

Simulations and models: why we use them and their limits
  • A model is a set of rules and data that represents a real system; a simulation runs the model to see what happens over time.
  • Simulations let people test situations that would be dangerous, costly or impossible in real life.
  • Variables can be changed to ask 'what if' questions and see how the outcome changes.
  • A simulation can be run faster or slower than real time, so long-term trends can be seen quickly.
  • Simulations help to predict outcomes and test ideas (hypotheses).
  • A simulation is only as good as its data and assumptions; if these are wrong, the results will be wrong.
  • Simulations can need a powerful processor because they handle large amounts of data and many calculations, sometimes with complex graphics.

Cloud storage: what it is, pros, cons and security
  • Cloud storage means saving files on remote servers owned by another company and reaching them over the internet.
  • You need an internet connection to upload or open files stored in the cloud.
  • Benefits include access from any place and any device, easy sharing and working together on files, and storage that can be scaled up or down.
  • Cloud providers usually keep backups, so files are not lost if your own device is lost or broken.
  • Drawbacks include needing a fast, reliable connection, relying on the provider, and ongoing subscription costs.
  • Security risks include hackers targeting the provider, dishonest staff at the provider, and files being intercepted during upload or download.
  • Security is shared: the user must choose strong passwords and keep them private; the provider must secure its servers, encrypt data, update security software and keep backups.

Input, process, output and other computational models
  • A computational model is a simple picture of how a computer turns a problem into a result.
  • The input-process-output (IPO) model has three stages, always in this order: input, then process, then output.
  • Input is the data that goes into the program, such as numbers typed by a user or a reading from a sensor.
  • Process is the work done on the inputs, such as a calculation or a decision.
  • Output is the result the program produces, such as a value on screen, a printed slip or a movement.
  • In a sequential model, instructions are carried out one after another, in order.
  • In a parallel model, a task is split into parts that different processors (or cores) work on at the same time.
  • In a multi-agent model, several separate systems (agents) talk to each other and work together towards one goal.
  • Only independent pieces of work can run in parallel; a step that needs earlier results must wait for them.

The stored program concept and the parts of the CPU
  • The stored program concept (from von Neumann) means both program instructions and data are kept together in main memory.
  • The CPU fetches the instructions from memory one at a time, decodes them and executes them.
  • A program instruction is a single command that tells the CPU what action to carry out.
  • A memory address is a number that identifies one location in memory, like a house number on a street.
  • The control unit (CU) controls the fetch-decode-execute cycle and sends signals to other parts of the computer.
  • The arithmetic logic unit (ALU) does calculations (such as adding) and logic comparisons (such as greater than).
  • Registers are tiny, very fast storage locations inside the CPU that hold data or addresses while they are being used.
  • Named registers include the program counter (PC), memory address register (MAR), memory data register (MDR), current instruction register (CIR) and accumulator (ACC).

What makes a CPU faster: clock speed, cores and cache
  • Clock speed is the number of cycles (pulses) the CPU clock makes each second, measured in hertz, for example 3 GHz = 3 billion cycles per second.
  • A higher clock speed means more fetch-decode-execute cycles each second, so more instructions are processed in the same time.
  • A higher clock speed also makes the CPU use more power and get hotter, so it needs more cooling.
  • A core is a separate processing unit inside the CPU; more cores can work on more instructions at the same time.
  • Cache is a small amount of very fast memory inside or close to the CPU.
  • Cache holds instructions and data that are used often, so the CPU does not have to wait for slower RAM.
  • A larger cache can hold more of these items, so the CPU finds what it needs in cache more often.
  • Other factors include the width of the data bus (word length) and the width of the address bus.

What the operating system does, and system vs application software
  • System software runs and looks after the computer itself; the operating system (OS) and utility programs are system software.
  • Application software lets the user do a task, such as writing a letter or editing a photo.
  • Operating system functions include process management, memory management, file management, peripheral (device) management, security and user management, and providing a user interface.
  • Multitasking on one CPU works because the OS scheduler gives each process a short time slice in turn.
  • Processes wait in a queue, and some processes may be given higher priority.
  • When storing a file, the OS checks there is enough free space and splits the file into blocks.
  • The blocks can be stored anywhere on the disc, and the OS records where each block is in a file allocation table.
  • The OS also stores metadata about each file, such as its permissions and the date it was created.

High-level and low-level languages
  • A high-level language (such as Python) uses English-like words and is easy for people to read and write.
  • A low-level language is close to the hardware: machine code (binary) or assembly language (short mnemonics such as ADD and LDA).
  • High-level code is portable: it can run on different types of computer once translated.
  • Low-level code is written for one type of processor, so it is not portable.
  • Low-level code can directly control hardware and registers, and can run fast using little memory.
  • Low-level code is harder to read, slower to write and easier to make mistakes in.
  • High-level languages provide built-in functions, libraries and tools that make programming easier.
  • Low-level languages are often used for device drivers and embedded systems; high-level languages for general applications.

Translators: assembler, compiler and interpreter
  • A translator converts source code into machine code that the CPU can run.
  • An assembler translates assembly language (low-level) into machine code.
  • A compiler translates the whole high-level program in one go and produces an executable file of object code.
  • Once compiled, the program runs without the compiler, runs quickly, and the source code does not need to be shared.
  • A compiler reports a list of errors after it has translated the whole program.
  • An interpreter translates and runs a high-level program one line at a time, every time it is run.
  • An interpreter stops when it reaches an error, which helps during testing, and the same source code can run on any machine that has the interpreter.
  • Assembled and compiled code can run without the translator in memory; interpreted code needs the interpreter each time.

Buses and the fetch-decode-execute cycle
  • A bus is a set of wires that carries signals between the CPU, memory and other parts.
  • The address bus carries memory addresses from the CPU to memory, in one direction only (unidirectional).
  • The data bus carries data and instructions in both directions between the CPU and memory (bidirectional).
  • The control bus carries control signals, such as memory read, memory write and clock signals, in both directions.
  • Fetch: the address in the program counter is copied to the memory address register (MAR), which puts it on the address bus; a read signal goes on the control bus, and the instruction comes back on the data bus.
  • The program counter holds the address of the next instruction and is increased (incremented) during the fetch.
  • Decode: the control unit works out what the instruction means. Execute: the instruction is carried out, for example by the ALU.
  • A wider data bus moves more bits at once; a wider address bus can point to more memory locations.

Write a logic statement for a problem
  • A logic statement (Boolean expression) uses letters for conditions and the operators AND, OR and NOT to show when something happens.
  • Use AND when all the conditions must be true together.
  • Use OR when any one of the alternatives is enough.
  • Use NOT when a condition must be false (for example, a lock removed or a code not entered).
  • The order of precedence is NOT first, then AND, then OR.
  • Put brackets around OR alternatives that must be joined to other conditions by AND, for example A AND (W OR D).
  • There can be more than one correct statement; equivalent versions earn full marks.
  • You can test your statement by building a quick truth table and checking a few rows against the story.

5-6 Communication, the internet and the bigger picture

Network types: LAN, WAN, PAN and why we network
  • A network is two or more computers or devices linked together so they can share data and resources.
  • Common reasons to network computers: share files, share hardware such as printers, share one internet connection, and let people communicate and work together.
  • Networks also let an organisation manage computers from one place: central backups, central software updates and central security settings.
  • A LAN (local area network) covers a small area such as one building or one site, and the organisation usually owns all of its equipment.
  • A WAN (wide area network) covers a large geographical area and joins separate LANs together, usually over links rented from telecoms companies; the internet is the biggest WAN.
  • A PAN (personal area network) connects devices around one person, for example a phone linked to earbuds by Bluetooth or a phone hotspot shared with a laptop.
  • Compared with a WAN, a LAN usually has higher bandwidth (more bits per second) and lower latency (less delay).
  • In the client-server model, a central server provides services such as file storage or logins, and the client computers ask it for them.
  • In the peer-to-peer model, every device is equal and shares directly with the others, with no central server.

Cyber attacks: phishing, shoulder surfing, eavesdropping and unpatched software
  • Social engineering means tricking people, rather than breaking technology, into giving away information or access.
  • Phishing is a social engineering attack: a fake email or message that pretends to come from a trusted organisation to get you to click a link or give personal details.
  • Signs of phishing include a generic greeting such as 'Dear Customer', a sender address that does not match the real company, urgent threats, spelling mistakes and a link to log in.
  • Pharming secretly redirects a user from a genuine website to a fake one that collects their details.
  • Shoulder surfing is watching someone, directly or with a camera, to see their password, PIN or private information as they type or read it.
  • Ways to stop shoulder surfing: cover the keypad, use a privacy screen filter, sit with your back to a wall, and avoid entering private details in public.
  • Eavesdropping is intercepting data while it travels across a network.
  • Unpatched software has security weaknesses that are publicly known, so attackers can use them until the patch (update) is installed.
  • Infected USB devices and other digital devices can bring malware into a network.

Keeping a network secure: access rights, physical security and authentication
  • Networks need protecting because they let malware spread between computers and let outsiders try to get in and steal or change data.
  • Access control gives each user only the rights they need for their job; common rights are none, read, write and execute.
  • A strong password policy forces long, complex passwords that are changed if compromised, making accounts harder to break into.
  • Authentication checks that a user really is who they claim to be.
  • Authentication methods include a username with a password, a security question, biometrics (fingerprint, face or iris) and two-factor authentication (2FA).
  • 2FA asks for two different kinds of proof, for example a password plus a one-time code sent to the user's phone.
  • Physical security protects the hardware itself, for example locked server rooms, swipe cards, CCTV cameras and security guards.
  • A firewall checks traffic coming into and leaving a network and blocks anything that breaks its rules.
  • Validation is different from authentication: validation checks that entered data is sensible and follows rules (such as a minimum length), while authentication checks identity.

Mobile generations: 3G, 4G and 5G
  • 3G, 4G and 5G are generations of mobile (cellular) communication standards; all of them are wireless.
  • Each newer generation gives higher bandwidth, meaning more data can be sent each second.
  • Each newer generation gives lower latency, meaning less delay between sending a request and getting a response.
  • 5G can connect many more devices in the same area, which suits the Internet of Things (everyday devices connected to the internet).
  • 5G uses new, higher radio frequency bands where much wider channels are available; wider channels carry more data each second, which gives 5G its higher bandwidth.
  • Higher frequencies travel shorter distances, so 5G needs more masts placed closer together.
  • For the user, these features mean faster downloads and streaming, quicker responses, and a more reliable connection in busy places.

Network protocols: what they are and which one does what
  • A protocol is a set of agreed rules that lets devices communicate, covering things like the format of data, its timing and how errors are checked.
  • Without shared protocols, devices made by different companies could not understand each other.
  • Ethernet is a family of protocols for wired LANs; it sets the cable and connector types, the speeds and how packets are checked for errors, and it works at the data link layer.
  • Wi-Fi is a family of protocols for wireless LANs that use radio waves.
  • HTTP (HyperText Transfer Protocol) moves web pages from a web server to a browser; HTTPS is the secure version that encrypts the data.
  • FTP (File Transfer Protocol) is used to move files between computers over a network.
  • SMTP (Simple Mail Transfer Protocol) is used to send email.
  • POP3 (Post Office Protocol 3) downloads email to one device and usually removes it from the server.
  • IMAP (Internet Message Access Protocol) keeps email on the server and keeps every device in step with it.

Network topologies: bus, ring, star and mesh
  • A topology is the layout of how the devices in a network are connected.
  • Bus: every device joins one shared main cable (the backbone) with a terminator at each end.
  • Bus: cheap and needs little cable, but if the main cable breaks the whole network fails, and it slows down with more devices because data collides more often.
  • Ring: devices are joined in a closed loop and data travels in one direction, so packets do not collide; if one link breaks the ring can fail.
  • Star: every device has its own cable to a central switch (or hub); one broken cable affects only that device and faults are easy to find.
  • Star: if the central switch fails, the whole network stops, and it needs more cable than a bus.
  • Mesh: each device is connected to several others (full mesh = every device connects to every other); there are many routes, so data can go around a broken link.
  • Mesh: very reliable but expensive, with lots of cabling and harder to set up and manage.
  • The internet is a huge partial mesh, which lets it grow and keep working when parts fail.

The internet, the web, DNS and the parts of a URL
  • The internet is the worldwide network of networks: the cables, routers and connected devices.
  • The World Wide Web (WWW) is a service that runs on the internet: the collection of web pages and other resources, linked by hyperlinks and fetched using HTTP or HTTPS.
  • Every device on the internet has an IP address, a number that identifies it, for example 2.20.38.113.
  • A domain name is the human-friendly name of a website, for example pearson.com.
  • The DNS (domain name system) works like a phone book: you give a DNS server a domain name and it returns the matching IP address.
  • A URL (uniform resource locator) is the full address of one resource on the web, for example https://www.pearson.com/computing/specification.html.
  • Reading a URL from left to right: the protocol (https), the domain name (www.pearson.com), the folder path (computing) and the file name (specification.html).
  • An ISP (internet service provider) is the company that connects homes and businesses to the internet.

Wired or wireless? Media, pros and cons, and network speed units
  • Wired networks send data along cables: copper twisted-pair cable carries electrical signals, and fibre-optic cable carries pulses of light.
  • Wireless networks send data through the air using radio waves; Wi-Fi uses the 2.4 GHz and 5 GHz frequency bands.
  • Advantages of wired: a steadier, more reliable connection that does not weaken with distance from the router or through walls, and it is harder for outsiders to intercept.
  • Wired links often give higher bandwidth (more bits per second) than wireless links.
  • Disadvantages of wired: cables must be installed and maintained, devices are tied to one place by the cable length, loose cables can be a trip hazard, and some devices such as phones have no network port.
  • Network data speeds are measured in bits per second, for example megabits per second (Mbps) and gigabits per second (Gbps).
  • Bytes and mebibits or mebibytes are units of storage, not network speed.
  • A personal hotspot can be better than free public Wi-Fi because fewer people share the bandwidth and only devices you allow can join, so it is more secure.

Connecting to the internet: switch, WAP, router and modem
  • A switch connects wired devices in a LAN and sends each packet only to the device it is meant for, using MAC addresses.
  • A wireless access point (WAP) lets wireless devices join the wired network; it is connected to the switch (or router) by a cable.
  • A router forwards packets between different networks, such as the home or office LAN and the internet.
  • A modem converts the digital data from the network into signals that can travel over the ISP's line, and converts incoming signals back.
  • The ISP (internet service provider) connects the modem to the rest of the internet.
  • The order from a device out to the internet is: device, switch, router, modem, ISP, internet.
  • Wired devices plug into the switch; wireless devices connect by radio to the WAP, and the WAP is cabled to the switch.
  • A home 'router' box usually combines a switch, a WAP, a router and a modem in one case.

Finding and fixing weaknesses: penetration testing, ethical hacking, code reviews, audit trails
  • A vulnerability is a weakness in a system that an attacker could use to get in or cause harm.
  • Penetration testing is an authorised, simulated attack on your own system to find its weaknesses so they can be fixed.
  • Ethical hackers ('white hat' hackers) break in with the owner's permission, do not steal or change data, and report what they find.
  • Commercial analysis tools are programs that automatically scan a network or software for known weaknesses and produce a report.
  • Network and user policies are the rules for how devices and people use the network; they should be reviewed regularly to keep up with new threats and laws.
  • A code review is when other programmers check code to find bugs, security holes and poor programming practices before it is released.
  • An audit trail is an automatic record of what was done on a system and who did it, which helps spot suspicious activity and trace problems back to their source.
  • Modular testing means testing each subprogram on its own as it is written, so errors are found early and in a small piece of code.
  • Secure design also includes thinking about security from the start, keeping operating systems updated and writing secure code.

IPv4 and IPv6: sizes, formats and why IPv6 exists
  • An IP address is a number that identifies a device on a network.
  • An IPv4 address is 32 bits long, written as four denary numbers from 0 to 255 separated by dots, for example 192.168.1.78.
  • Each IPv4 number is 8 bits (one byte), so 4 x 8 = 32 bits.
  • An IPv6 address is 128 bits long, written as eight groups of four hexadecimal digits separated by colons.
  • Each hexadecimal digit stands for exactly 4 bits, because 4 bits give 16 values (0-F).
  • So each IPv6 group is 4 x 4 = 16 bits, and the whole address is 8 x 16 = 128 bits (or 32 hex digits x 4 bits).
  • IPv6 was introduced because the number of internet-connected devices grew so much that IPv4 was running out of addresses.
  • IPv4 allows about 4.3 billion addresses (2 to the power 32); IPv6 allows vastly more (2 to the power 128).

Protecting software by law: copyright, patents, trademarks and licences
  • Intellectual property (IP) is a creation of the mind, such as software, music or an invention, that belongs to its creator.
  • Copyright protects the actual code and other written or creative work; it applies automatically as soon as the work is created, without having to apply.
  • A patent protects a new invention or technical process; it must be applied for and lasts for a fixed time.
  • A trademark protects a brand name or logo, such as a product's name.
  • A licence is a legal agreement that sets out how software may be used; buying software usually buys a licence to use it, not ownership of it.
  • Proprietary licences do not allow users to view, change or share the source code.
  • Free and open-source (FOSS) licences allow users to study, change and share the code.
  • Creative Commons licences let creators allow sharing and reuse on conditions they choose.
  • Software can be protected from illegal copying with licence keys and online registration or activation.

The TCP/IP model: four layers and what each does
  • Data sent over a network is broken into small pieces called packets.
  • The TCP/IP model has four layers, from top to bottom: application, transport, network and data link.
  • Application layer: holds the protocols that programs use, such as HTTP, FTP and SMTP, and talks to the user's software.
  • Transport layer: on sending, splits data into packets and numbers them; on receiving, checks they all arrived, puts them back in order and asks for any missing or damaged ones to be sent again.
  • Network layer: adds the sender's and receiver's IP addresses and routes each packet across networks towards its destination.
  • Data link layer: moves the packets across the physical connection between two devices, using MAC addresses.
  • When sending, data passes down the layers; when receiving, it passes back up, and each layer removes what its partner layer added.
  • Using layers means each layer can be changed or fixed without changing the others.

Ethics of technology: privacy, inclusion and professionalism
  • Inclusion means everyone being able to use technology; barriers include cost, no internet or devices where they live, lack of skills, disability, or simply not wanting to.
  • Some people avoid online services because they do not trust them, worry about hacking, or would rather talk to a real person.
  • Privacy is a person's right to control information about themselves.
  • Surveillance systems such as cameras with facial recognition collect personal data, so the people affected should give consent and know how it will be used.
  • Data protection laws require organisations to keep personal data secure, use it only for stated purposes and not keep it longer than needed.
  • Facial recognition can be biased, making more mistakes for some groups of people.
  • Computing professionals show professionalism by behaving legally and ethically, following a code of conduct, testing their code properly and keeping their skills up to date.
  • Professionals should respect users' privacy, avoid bias, and make software accessible to everyone.

Technology, the environment and health
  • Making computers uses large amounts of energy and water and causes air and water pollution.
  • Devices need metals such as copper, gold and lithium; mining them uses up limited resources and can poison soil and groundwater.
  • Running computers and data centres uses a lot of electricity, including for cooling.
  • E-waste (thrown-away electronics) contains toxic materials; in landfill these can leak into the ground and water.
  • Ways to reduce the impact: switch devices off when not in use, lower screen brightness, keep devices longer, repair them, recycle them properly, or donate them.
  • Keeping a device longer means fewer new devices are made, so less manufacturing and less e-waste.
  • Wearable technology such as smartwatches can benefit health by measuring heart rate, steps, sleep and blood oxygen, and by encouraging exercise.
  • Wearables can share data with phone apps and doctors, and can send alerts, but they only help if the user acts on the information.

Emerging tech: quantum, DNA computing, AI and nanotechnology
  • Classical computers store data as bits, each 0 or 1.
  • Quantum computers store data in qubits (quantum bits), made from sub-atomic particles such as electrons or photons.
  • Superposition means a qubit can be in a combination of 0 and 1 at the same time; its value is only fixed when it is measured.
  • Entanglement links pairs of qubits so that the state of one affects the other; together with superposition this lets quantum computers explore many possibilities at once.
  • DNA computing uses strands of DNA and chemical reactions, instead of silicon chips and electricity, and can run huge numbers of operations in parallel.
  • DNA uses a four-letter code (A, C, G, T) rather than the two binary digits 0 and 1.
  • Artificial intelligence (AI) is software that learns patterns from large sets of training data and uses them to make predictions or decisions about new data.
  • AI is used in medical diagnosis, chatbots, face and speech recognition, recommendations, game playing and self-driving vehicles.
  • AI raises ethical issues: biased training data can give unfair results, it can be hard to know if its answer is right, and some jobs may be replaced.
  • Nanotechnology is engineering at the scale of atoms and molecules, roughly 1 to 100 nanometres; uses include tiny transistors, scratch-resistant coatings and medicines delivered to exact places in the body.

Finish an if/elif/else so each input gives the right message
  • A condition is a test that is either True or False, such as aNum > 0.
  • Relational operators compare values: < less than, <= at most, > more than, >= at least, == equal to, != not equal to.
